# Сравнение данных для обнаружения транспорта

Измеренные ниже mAP относятся к нашей пятикомпонентной задаче на VisDrone, а не к официальным рейтинговым протоколам этих датасетов. Выборка с более высоким mAP может просто содержать более крупные и простые объекты. По опубликованным значениям разных моделей на разных выборках нельзя определить, какой набор улучшит нашу дорожную камеру.

| Датасет | Съемка и объем | Пригодность для проекта | Ограничение сравнения |
|---|---|---|---|
| VisDrone DET | Камеры на дронах; в нашей версии 6469 train, 547 val, 1610 test-dev | Уже обучены и измерены пять классов; много мелких объектов | Ракурс отличается от наземной дорожной камеры; ignored regions не маскируются в нашем протоколе |
| UA-DETRAC | 100 дорожных видеопоследовательностей, более 140000 кадров | По типу съемки наиболее близок нашей демонстрационной камере; полезен для детекции и трекинга | Категории car/bus/van/others; others включает грузовики и спецмашины, его нельзя автоматически переименовать в truck; нет соответствующей пятикомпонентной задачи |
| BDD100K | 100000 видео, разнообразные погодные и географические условия; несколько задач | Кандидат для разнообразия освещения и погоды | Съемка из автомобиля; необходимо выбрать именно detection-разметку и явно согласовать категории, полноту разметки и правила игнорирования |
| KITTI Object | 7481 train и 7518 test изображений; левый цветной архив 12 GB | Дополнительная проверка автомобильных дорожных сцен | Другой ракурс, классы и официальный протокол; тестовые метки не предоставляются как обычная локальная выборка |

UA-DETRAC теперь проверен на первых 300 кадрах MVI_39031 по опубликованным тестовым XML: [результаты](DETRAC_RESULTS.md). Обучение на нём не проводилось; расширение на другие сцены временно ограничено квотой авторского Google Drive. BDD100K и KITTI нашей моделью ещё не оценивались. Таблица выше сравнивает содержание и применимость.

Источники: [VisDrone, официальный репозиторий](https://github.com/VisDrone/VisDrone-Dataset), [UA-DETRAC, статья авторов](https://arxiv.org/html/1511.04136v4), [BDD100K, статья авторов](https://arxiv.org/abs/1805.04687), [KITTI, официальный протокол и загрузки](https://www.cvlibs.net/datasets/kitti/eval_object.php?obj_benchmark=2d).

## Что уже измерено

Основная модель vehicle-finetune-full: test mAP50 = 0.34413, mAP50-95 = 0.20290, precision = 0.46075, recall = 0.35828. Это не процент правильно подсчитанных физических машин. Детекция, сохранение ID и события пересечения оцениваются отдельно.

Разметка train: car 144842, van 24954, truck 12874, bus 5926, motorcycle 29646. Добавление разнообразных реальных автобусов и грузовиков может быть полезнее, чем увеличение уже доминирующего класса car; улучшение нужно измерять.

## Контролируемое расширение текущих данных

Подготовлены 1024 исходных изображения из тренировочного pilot-списка и 1024 преобразованные версии: отражение по горизонтали с исправлением координаты x рамок, изменение яркости/контраста и мягкое размытие части изображений. Валидатор исключает совпадение SHA256 с val/test. Геометрические размеры рамок сохраняются. Независимых новых сцен: **0**. Это аугментация, не новый внешний датасет.

Два коротких дообучения стартуют из одного best.pt основной модели, по 3 эпохи, 640 px, batch 8, AdamW lr0=0.0001, seed 42. Контроль содержит 1024 оригинала дважды; расширенный вариант — оригиналы плюс варианты. Оба имеют 2048 примеров и 256 batch на эпоху; встроенные преобразования YOLO одинаковы. Такое сравнение помогает отделить эффект преобразований от большего количества шагов. На MPS остается недетерминизм, один seed не дает оценки статистической надежности.

Выбор модели проводится по validation mAP50-95. Уже использованная в предыдущих экспериментах test-dev оценивается описательно; это не новая слепая проверка. Результаты сохраняются в augmentation-comparison.json после завершения обеих попыток. Короткий эксперимент не доказывает оптимальность настройки для полного корпуса.

## Для честного сравнения внешних датасетов

Нужна общая независимо размеченная выборка из целевых дорожных камер, разделенная по видео/камере, а не случайным соседним кадрам. Требуются одинаковые классы и полнота разметки, одна архитектура, сопоставимый бюджет шагов, одинаковый размер изображений и единый код оценки. Результаты следует давать отдельно по классам, размерам объектов и погоде; пропуски/лишние события подсчета проверять независимо от mAP. Если внешний набор не размечает один из пяти классов, простое смешивание создаст ложные фоновые примеры этого класса.

Для последующего полноценного обучения подготовлен configs/visdrone-expanded-full.yaml: 7493 тренировочных файла (6469 оригиналов + 1024 варианта). Приведенный контролируемый эксперимент использует 2048 примеров, не весь этот список.

У UA-DETRAC официальный detection-протокол использует IoU 0.7 и усреднение AP по 11 уровням recall ([описание авторов](https://arxiv.org/html/1511.04136v4)). Наши mAP50 и mAP50-95 вычисляются иначе, поэтому числа из его рейтинга нельзя напрямую сопоставлять с нашими.

Полный расширенный YOLO-набор проверен scripts/audit_dataset.py: проверены чтение изображений, наличие меток, допустимость категорий и рамок, отсутствие одинаковых SHA256 между выборками. Результат: expanded-dataset-audit.json. Эта проверка не является аудитом полноты аннотаций и независимости камер.

Диагностика размеров объектов (dataset-diagnostics.json): на test при пропорциональном уменьшении длинной стороны до 640 px минимальная сторона меньше 10 px у 46.1% car, 39.3% van, 23.9% truck, 21.6% bus и 75.0% motorcycle. Медиана минимальной стороны motorcycle — 7.0 px. Это описательная статистика без встроенных геометрических преобразований обучения; она не доказывает причину конкретных ошибок. Поэтому дополнительно исследуется размер входа 960 px на том же checkpoint, с выбором по validation.
