# Запуск проекта

## На этом компьютере

1. Откройте `run_app.command` в папке проекта.
2. В браузере откройте http://127.0.0.1:8501.
3. Выберите видео и модель. Задайте горизонтальную линию или точки A и B, проверьте предпросмотр. Нажмите «Обработать видео».
4. Проверьте размеченное видео и скачайте таблицы.
5. Для оценки событий откройте «Проверка подсчёта». Можно загрузить JSON или ввести разметку по исходным кадрам прямо в приложении.

Текущий сервер уже может занимать порт 8501. В этом случае используйте открытый адрес, а не запускайте второй экземпляр.

## На другом компьютере

Используйте Python 3.10–3.13. Проверенное окружение — Python 3.10 на Apple Silicon.

```sh
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python -m pip install -e . --no-deps
python scripts/rebase_paths.py
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501 --browser.gatherUsageStats false
```

На Windows активация: `.venv\Scripts\activate`. Выбирайте CPU, если MPS отсутствует. Зафиксированные версии могут не иметь пакетов для иной платформы; тогда установите зависимости через `python -m pip install -e .` и запишите новые версии.

Поставляемый компактный архив не содержит виртуального окружения и многогигабайтного корпуса. Обученные веса и документация включены. Для повторного обучения:

```sh
python scripts/download_data.py
python scripts/prepare_visdrone.py --pilot-size 1024
python scripts/run_experiment.py --name vehicle-finetune-reproduction --data configs/visdrone-vehicles.yaml --epochs 10 --imgsz 640 --batch 8 --device mps
```

Данные скачиваются из документированного зеркала VisDrone. Используйте новый каталог эксперимента для каждого запуска. Обработанные видео и модели можно применять локально без повторного скачивания корпуса.

## Результаты

- `reports/vehicle-*.json` — параметры и метрики завершенных обучений.
- `reports/EXPERIMENT_REPORT.md` — общий отчет.
- `outputs` — размеченные видео и таблицы запусков.
- `tests` — проверки логики; они не являются оценкой точности CNN.

Счет пересечений может содержать пропуски и повторения. Для проверки точности необходима независимая разметка исходного видео. Пиксельное движение не означает скорость в км/ч.

## Проверка архива после сборки

```sh
python scripts/package_practical.py
python scripts/verify_practical.py
```

Второй скрипт проверяет размер и SHA256 каждого файла, распаковывает проект во временную папку, переносит внутренние пути и запускает тесты, включая обработку короткого видео обученной моделью на CPU. Это проверка переносимости в том же Python-окружении, а не подтверждение совместимости со всеми операционными системами.

## Исследование расширения тренировочных примеров

После скачивания/подготовки исходного VisDrone:

```sh
python scripts/expand_training.py
python scripts/run_augmentation_comparison.py
python scripts/report_augmentation.py
```

Сравнение запускает два дообучения основной модели по 3 эпохи на одинаковом числе примеров: контроль и аугментация. Требуются Apple MPS и базовые обученные веса. Если эти имена экспериментов уже заняты, выбирайте новые имена через run_experiment.py, сохраняя одинаковые параметры сравнения.

Для дальнейшего обучения на всем расширенном наборе есть configs/visdrone-expanded-full.yaml: 6469 оригиналов + 1024 преобразованных изображения = 7493 тренировочных файла. Набор не входит целиком в компактный архив, но воспроизводится скриптом expand_training.py. Это 1024 дополнительных варианта, а не новые независимые сцены.

Перед обучением на новом или объединенном YOLO-наборе проверьте его:

```sh
python scripts/audit_dataset.py --data configs/visdrone-expanded-full.yaml --output reports/my-dataset-audit.json
```

Проверяются изображения, наличие txt-разметки, классы, координаты рамок и точные дубликаты между выборками. Для отрицательного изображения нужен явно пустой txt-файл. Проверка не подтверждает полноту разметки или независимость камер/сцен.

Для нового корпуса используйте шаблон configs/vehicles.yaml. ID классов: 0 car, 1 van, 2 truck, 3 bus, 4 motorcycle. Разделяйте материалы по камерам/видео; соседние кадры одного ролика должны оставаться в одной выборке. Не смешивайте датасеты с отсутствующей разметкой одного из этих классов без отдельного согласования протокола.

## Размер входа CNN

В интерфейсе можно выбирать 416/640/960/1280 px. Размер сохраняется в summary.json вместе с результатом обработки. Для одной обученной модели можно сравнить 640 и 960 на неизмененных выборках:

```sh
python scripts/compare_resolution.py --name vehicle-expanded-full --imgsz 960 --device mps
```

Результаты пишутся в reports/resolution-comparison.json; размер для интерфейса выбирается по validation mAP50-95. Более высокое разрешение требует больше ресурсов; отдельно проверяйте скорость и подсчет на целевой камере. Повторный запуск с уже существующим отчетом не перезаписывает его.
