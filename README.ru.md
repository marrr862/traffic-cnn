# Анализ движения транспорта с использованием CNN

Python-приложение для дипломной темы «CNN- Տեսաշարերի միջոցով տրանսպորտային միջոցների շարժման և երթևկության հոսքի վերլուծության ծրագրային միջոցի մշակում».

Реализованы обучение YOLOv8n, отслеживание ByteTrack, поддержка коротких разрывов траектории, стабилизация класса, подсчет пересечений конечной линии и анализ движения. Локальный интерфейс принимает видео, показывает результат и экспортирует таблицы.

## Быстрый запуск

Подробные шаги установки и переноса: [QUICKSTART.md](QUICKSTART.md).

На подготовленном компьютере запустите `run_app.command` и откройте http://127.0.0.1:8501. Через терминал:

```sh
source .venv/bin/activate
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501 --browser.gatherUsageStats false
```

Выберите демонстрационное или свое видео, модель, положение линии и устройство. Новые результаты сохраняются отдельно; готовые файлы не перезаписываются. Модели упорядочены по validation mAP50–95, а не по test.

## Данные и обучение

Подготовлен VisDrone2019-DET: 6469 train, 547 val, 1610 test изображений. Пять категорий: car, van, truck, bus, motorcycle. Рамок в train: 218242. Три точных повтора исключены; контрольные суммы и преобразования сохранены в `reports/dataset.json`.

Источники: [VisDrone](https://github.com/VisDrone/VisDrone-Dataset), [документация корпуса](https://docs.ultralytics.com/datasets/detect/visdrone/). Игнорируемые области не маскируются; это адаптированная задача пяти классов, а не официальный балл соревнования. Съемка с дрона отличается от стационарной дорожной камеры.

Воспроизведение данных:

```sh
python scripts/download_data.py
python scripts/prepare_visdrone.py --pilot-size 1024
```

Сопоставимое пилотное сравнение на 1024 изображениях:

```sh
python scripts/run_experiment.py --name vehicle-scratch-repeat --scratch --epochs 15 --imgsz 416 --batch 8 --device mps
python scripts/run_experiment.py --name vehicle-finetune-repeat --epochs 15 --imgsz 416 --batch 8 --device mps
```

Основной опыт на полном train:

```sh
python scripts/run_experiment.py --name vehicle-full-repeat --data configs/visdrone-vehicles.yaml --epochs 10 --imgsz 640 --batch 8 --device mps
python scripts/make_report.py
```

На другом устройстве используйте CPU или совместимый GPU. Каждый повтор требует нового имени. Seed 42 сохраняется, но MPS не гарантирует полную детерминированность. Лучшая эпоха выбирается по validation. Итоговые параметры, фактически завершенные эпохи, версии и тестовые метрики — в `reports/vehicle-*.json`.

Разные размеры входа и объемы train в pilot и full не позволяют объяснить изменение качества только инициализацией. Число эпох является ограничением выполненного опыта, а не доказательством сходимости.

## Консольная обработка

```sh
traffic-cnn analyze --video data/video/vehicles.mp4 --weights runs/experiments/vehicle-finetune-full/weights/best.pt --output outputs/my-video --line 0 1296 3839 1296 --conf .3 --imgsz 640 --device cpu
```

Линия задается в пикселях исходного видео. Без `--line` используется горизонтальный отрезок на 60% высоты. Произвольная ориентированная линия доступна в CLI и интерфейсе через режим «По двум точкам»; положение отрезка видно в предпросмотре. По умолчанию используется стандартный ByteTrack. Флаг `--baseline-tracking` задает его явно; `--continuity-tracking` включает экспериментальные объединение фрагментов и историю класса. На полном детекторе экспериментальный режим дал 8 совпадений против 9 у стандартного по предварительным интервалам, поэтому он не выбран по умолчанию.

Порог интерфейса задает уверенность инициализации трека. Детектор сохраняет менее уверенные рамки для восстановления существующих треков. Фактические параметры сохранены в `tracker.yaml` и `summary.json`.

## Файлы результата

| Файл | Содержимое |
|---|---|
| annotated.mp4 | Рамки, траектории, линия и счет |
| crossings.csv | Отдельные переходы, время, ID, класс и направление |
| flow_windows.csv | Счет по направлениям, среднее и максимум машин в кадре по временным интервалам |
| tracks.csv | Наблюдения с исходным и каноническим ID |
| tracks_summary.csv | Длительность, пиксельный путь и смещение |
| frame_stats.csv | Видимые машины и накопленный счет по времени |
| summary.json | Сводка, модель, пороги и скорость обработки |
| tracker.yaml | Конфигурация отслеживания |

Опорная точка — середина нижней стороны рамки. Четырехпиксельная зона около линии подавляет колебания; отрезок конечен; один канонический ID учитывается один раз. Длинные пропуски не интерполируются для учета. Эвристика непрерывности связывает только однозначный недавно потерянный фрагмент с достаточным IoU прогнозируемой рамки. Она не гарантирует идентичность физического автомобиля.

Интенсивность равна N × 3600 / T при T в секундах. Пересчет короткой записи не означает реальный часовой поток. Пиксельный путь зависит от перспективы и шума рамки. Скорость в км/ч и плотность машин на километр требуют калибровки и не вычисляются.

## Проверки и материалы диплома

```sh
python -m unittest discover -s tests -v
python scripts/evaluate_counting.py --results outputs/demo-full-continuity --name my-counting-check
```

Тесты проверяют геометрию, непрерывность, преобразование данных, экспорт и открытие интерфейса. Они не определяют качество CNN. Предварительный визуальный ориентир первого ролика подготовлен ассистентом, требует независимой проверки человеком и используется как разработочный пример. Равенство общего счета может скрывать пропуски и повторения. Второй ролик проверяет работу на другой записи; без разметки его счет не является оценкой точности.

Текст: `thesis/DIPLOMA.docx`, источник глав `thesis/CHAPTERS.md`, экспериментальный отчет `reports/EXPERIMENT_REPORT.md`. Титульные сведения и оформление под требования конкретной кафедры требуют заполнения. Полные результаты и ограничения изложены в отчете, без обещания заранее заданной точности.

Библиотечные методы: [обучение Ultralytics](https://docs.ultralytics.com/modes/train/), [отслеживание](https://docs.ultralytics.com/modes/track/), [ByteTrack](https://arxiv.org/abs/2110.06864). Собственная реализация охватывает подготовку транспортного корпуса, эксперимент, геометрию учета, непрерывность, экспорт и интерфейс.


## Практическая проверка своих видео

Во вкладке «Проверка подсчёта» выберите завершенный результат. Режим «Разметка в приложении» показывает исходные кадры без предсказаний CNN. Перемещайтесь по кадрам, отмечайте интервал пересечения, класс и направление каждой физической машины. События сохраняются локально в manual-reference.json; запись можно удалить и выгрузить JSON. Точность введенной разметки и независимость проверки должны быть установлены человеком.

Для горизонтального отрезка A→B слева направо negative_to_positive означает движение вниз по кадру. При изменении порядка точек направления меняются. Для наклонного отрезка они обозначают переход на положительную или отрицательную сторону ориентированной прямой, а не географическое направление.

Оценка допускается только при совпадении SHA-256 исходного видео, FPS и координат линии. Отчет содержит взаимно однозначные сопоставления, пропуски, лишние события, ошибки класса, precision/recall/F1 событий. Встроенный предварительный пример не является независимым эталоном.

```sh
python scripts/evaluate_counting.py --results outputs/practical-flow --name practical-flow --reference reports/video-reference.json --tolerance 6
python scripts/package_practical.py
```

Практический архив deliverables/traffic-cnn-practical.zip содержит код, веса, примеры и результаты без Word, презентации, виртуального окружения и полного обучающего корпуса. Инструкция переноса — QUICKSTART.md.

### Сравнение датасетов и расширение

Содержание VisDrone, UA-DETRAC, BDD100K и KITTI сравнивается в `reports/DATASET_COMPARISON.md`. Метрик нашей модели на трех внешних наборах пока нет. Их опубликованные AP нельзя использовать как доказательство, какой набор лучше для этой камеры: отличаются классы, ракурсы и правила оценки.

`python scripts/expand_training.py` создает 1024 тренировочных варианта с корректным отражением рамок, изменением яркости/контраста и мягким размытием. Полный список `configs/visdrone-expanded-full.yaml` содержит 7493 файла; новых независимых сцен нет. Val/test не изменяются. Данные и варианты воспроизводятся из исходного корпуса, но не включаются в компактный архив.

`python scripts/run_augmentation_comparison.py` сравнивает два трехэпоховых продолжения основной модели: по 2048 примеров за эпоху, контроль и аугментация. `python scripts/report_augmentation.py` сохраняет таблицу, график и рекомендацию по validation. Результаты — `reports/AUGMENTATION_RESULTS.md`, `reports/augmentation-comparison.json`; дополнительно может включаться полное дообучение `vehicle-expanded-full`, для которого нет полного контрольного продолжения и эффект аугментации отдельно не установлен.

Для своего полностью размеченного YOLO-корпуса используйте пятикомпонентный шаблон `configs/vehicles.yaml` и `scripts/audit_dataset.py`. У всех изображений, в том числе отрицательных, должны быть txt-метки. Неразмеченные объекты одного из наших классов нельзя автоматически считать фоном. Делите материал по камерам/видеопоследовательностям, а не по соседним кадрам.

## Внешняя проверка и чистая установка

Опубликованные тестовые кадры и XML UA-DETRAC использованы для проверки переноса модели на другую дорожную камеру. Численные результаты и ограничения: `reports/DETRAC_RESULTS.md`. Обучение на UA-DETRAC не выполнялось. Проверена первая сцена (300 кадров); дополнительные сцены пока недоступны из-за квоты авторского архива Google Drive.

```bash
python scripts/download_detrac.py --sequence MVI_39031
python scripts/evaluate_detrac.py --sequence MVI_39031 --device cpu
python scripts/report_detrac.py
```

Для повторной проверки нужно удалить или перенести папку соответствующего результата `outputs/demo-full-detrac-*`: скрипт использует существующую завершённую обработку видео. Исходные JPG внешнего набора не входят в компактный архив; XML, их SHA256-манифест, построенное видео и результаты включены.

Проверка установки с нуля на этом Mac:

```bash
python3.10 -m venv .venv-clean
source .venv-clean/bin/activate
python -m pip install -e .
python -m pip check
python -m unittest discover -s tests -v
```

33 теста прошли в новом окружении без system-site-packages. Зафиксированные версии — `reports/requirements-clean-macos.txt`; журнал — `reports/clean-install.log`. Это проверка на том же Mac, а не подтверждение работы на Windows/Linux или другом физическом компьютере.
