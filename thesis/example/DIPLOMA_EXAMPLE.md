# ՆԵՐԱԾՈՒԹՅՈՒՆ

Ճանապարհային երթևեկության կառավարումը, ճանապարհների պլանավորումը և երթևեկության անվտանգության գնահատումը պահանջում են տվյալներ հոսքի մասին՝ քանի տրանսպորտային միջոց է անցնում հատույթով, ինչ արագությամբ, որ ուղղությամբ և ինչպիսի խտությամբ։ Ավանդաբար այդ տվյալները հավաքվում են ձեռքով հաշվարկով կամ ճանապարհի մեջ տեղադրված ինդուկտիվ օղակներով և ռադարներով։ Ձեռքով հաշվարկը աշխատատար է և կարճատև, իսկ ներկառուցված սենսորները թանկ են, պահանջում են ճանապարհային աշխատանքներ և չեն տալիս տեսողական տեղեկություն։

Տեսախցիկներն արդեն տեղադրված են բազմաթիվ խաչմերուկներում և մայրուղիներում։ Տեսանյութը պարունակում է ամբողջ տեղեկությունը յուրաքանչյուր մեքենայի դիրքի, դասի և շարժման մասին, սակայն այն պետք է վերածել քանակական ցուցանիշների։ Վերջին տասնամյակում փաթույթային նեյրոնային ցանցերը (CNN) կտրուկ բարելավել են պատկերներում օբյեկտների հայտնաբերման ճշտությունը, իսկ YOLO ընտանիքի մեկ փուլանի դետեկտորները հնարավորություն են տալիս մշակել տեսանյութը սովորական համակարգչով՝ իրական ժամանակին մոտ արագությամբ։

Միայն հայտնաբերումը բավարար չէ հոսքը չափելու համար։ Մեկ մեքենան տեսադաշտում կարող է մնալ մի քանի վայրկյան և հայտնաբերվել հարյուրավոր կադրերում, իսկ հարևան մեքենաների ծածկումը, մասշտաբի փոփոխությունը և շրջանակի անկայունությունը ստեղծում են դիտարկման ընդհատումներ։ Ուստի անհրաժեշտ է նաև հետագծում, այսինքն՝ նույն ֆիզիկական մեքենայի դիտարկումների միավորում մեկ նույնացուցիչի (ID) ներքո, հաշվման կանոն, որը յուրաքանչյուր մեքենան հաշվում է ճիշտ մեկ անգամ, և երկրաչափական մոդել, որը պիքսելները վերածում է մետրերի։

**Հետազոտության օբյեկտը** ճանապարհային տեսախցիկների տեսանյութերն են և տրանսպորտային միջոցների նշագրված պատկերները։ **Հետազոտության առարկան** փաթույթային դետեկտորի, բազմաօբյեկտային հետագծման և երկրաչափական տրամաչափման համադրությունն է երթևեկության հոսքի չափման համար։

**Գիտական և գործնական նորույթը**: աշխատանքում ներկայացված է ամբողջական, վերարտադրելի համակարգ՝ տվյալների պատրաստումից մինչև հոսքի մակրոսկոպիկ բնութագրեր։ Սեփական մշակումներից են գծի հատման կանոնը՝ հիստերեզիսով, կադրում արդեն գծից անցած մեքենաների հաշվարկը և նույն մեքենայի կրկնակի ID-ների զտիչը, արագության գնահատումը սահող ժամանակային պատուհանով, ֆիզիկական հավաստիության ստուգումը (արագացված տեսանյութերի հայտնաբերում q = k·v հավասարման և գոտու թողունակության միջոցով) և սալիկային հայտնաբերումը՝ եզրերով կտրված օբյեկտների հեռացմամբ։ Մոդելների համեմատությունը կատարված է մի քանի տիրույթներում՝ անօդաչու սարքի պատկերներ, անշարժ ճանապարհային տեսախցիկներ և արտաքին UA-DETRAC հավաքածու։

**Գործնական արժեքը**: ծրագիրն աշխատում է սովորական նոութբուքի վրա (Apple M4 պրոցեսորով համակարգչում 4K տեսանյութը մշակվում է մոտ 13 կադր/վ արագությամբ), ունի հայերեն միջերես, ընդունում է ինչպես պատրաստի տեսանյութեր, այնպես էլ IP տեսախցիկների ուղիղ հոսք։ Այն կարող է օգտագործվել երթևեկության ուսումնասիրությունների, ուսումնական նպատակների և ավելի մեծ համակարգերի նախատիպի համար։

Ծրագրի ելակետային կոդը, ուսուցանված մոդելները և փորձերի արդյունքները հրապարակված են https://github.com/marrr862/traffic-cnn պահոցում։

Աշխատանքը բաղկացած է ներածությունից, խնդրի դրվածքից, վեց գլխից, եզրակացություններից, գրականության ցանկից և հավելվածներից։

Առաջին գլուխը տեսական մասն է, որտեղ նկարագրված են երթևեկության հոսքի բնութագրերը, տվյալների հավաքման եղանակները, փաթույթային նեյրոնային ցանցերի և YOLOv8 դետեկտորի կառուցվածքը, ինչպես նաև հետագծման և տրամաչափման մեթոդները։ Երկրորդ գլուխը վերլուծական մասն է, որտեղ ներկայացված են ուսուցման և ստուգման տվյալների պատրաստումը, փորձարարական ստուգման մեթոդիկան և CNN-ի ուսուցման փորձերի համեմատական վերլուծությունը։ Երրորդ գլուխը գործնական մասն է, որտեղ նկարագրված են ծրագրային միջոցի ճարտարապետությունը, ալգորիթմները, օգտագործողի միջերեսը և տեսանյութերի վերլուծության արդյունքները։

Չորրորդ, հինգերորդ և վեցերորդ գլուխներում ներկայացված են տնտեսագիտության, բնապահպանության և կենսագործունեության անվտանգության հարցերը։

# ԽՆԴՐԻ ԴՐՎԱԾՔԸ

Երթևեկության կազմակերպման, լուսացույցային կարգավորման և ճանապարհային ցանցի պլանավորման համար անհրաժեշտ են ճշգրիտ և պարբերաբար թարմացվող տվյալներ տրանսպորտային միջոցների քանակի, դասերի, շարժման ուղղությունների, արագությունների և խտության մասին։ Ձեռքով հաշվարկը աշխատատար է և կարճատև, իսկ ճանապարհի ծածկույթում տեղադրվող տվիչները թանկ են և տալիս են միայն մեկ կետի տվյալներ։ Միևնույն ժամանակ քաղաքներում և մայրուղիներում արդեն տեղադրված են բազմաթիվ տեսախցիկներ, որոնց տեսանյութերը կարելի է ավտոմատ կերպով վերածել երթևեկության քանակական ցուցանիշների։

Ավարտական աշխատանքի նպատակն է մշակել Python լեզվով ծրագրային միջոց, որը տեսախցիկի տեսանյութից կամ ուղիղ հոսքից փաթույթային նեյրոնային ցանցի միջոցով հայտնաբերում և դասակարգում է տրանսպորտային միջոցները, հետագծում է դրանց շարժումը և հաշվարկում է երթևեկության հոսքի հիմնական բնութագրերը, ինչպես նաև փորձարարականորեն գնահատել դրա ճշտությունը։

Նպատակին հասնելու համար անհրաժեշտ է կատարել հետևյալ խնդիրները.

- վերլուծել երթևեկության հոսքի բնութագրերը և օբյեկտների հայտնաբերման ու հետագծման ժամանակակից մեթոդները,
- պատրաստել տրանսպորտային միջոցների նշագրված կորպուս բաց աղբյուրներից (VisDrone2019-DET, MIO-TCD) և ստուգել դրա ամբողջականությունը,
- ուսուցանել CNN դետեկտոր և համեմատել ուսուցման տարբեր եղանակներ վերարտադրելի փորձերով,
- իրականացնել հետագծում, հաշվման գծերով հաշվարկ, արագության, խտության և սպասարկման մակարդակի հաշվարկ,
- մշակել օգտագործողի հայերեն միջերես և արդյունքների արտահանում,
- գնահատել հայտնաբերման և հաշվարկի ճշտությունը, այդ թվում՝ ուսուցման մեջ չօգտագործված արտաքին տվյալներով,
- կատարել ծրագրային միջոցի տեխնիկատնտեսական հաշվարկ, քննարկել բնապահպանության և կենսագործունեության անվտանգության հարցերը։

Ծրագրային միջոցը պետք է բավարարի հետևյալ պահանջներին.

- մուտքային տվյալներ՝ տեսաֆայլ (MP4, AVI, MOV, MKV) կամ ուղիղ հոսք (համակարգչի տեսախցիկ, IP տեսախցիկ, HLS հասցե, YouTube),
- յուրաքանչյուր կադրում տրանսպորտային միջոցների հայտնաբերում և հինգ դասի (մարդատար, ֆուրգոն, բեռնատար, ավտոբուս, մոտոցիկլ) որոշում,
- միջկադրային հետագծում կայուն նույնացուցիչներով և մեկ կամ մի քանի հաշվման գծերի հատումների հաշվարկ՝ ըստ ուղղությունների և դասերի,
- տրամաչափման դեպքում՝ արագության (կմ/ժ), խտության (մեքենա/կմ) և սպասարկման մակարդակի որոշում, արդյունքների ֆիզիկական հավաստիության ստուգում,
- հայերեն գրաֆիկական միջերես և արդյունքների արտահանում CSV, JSON և MP4 ձևաչափերով,
- աշխատանք սովորական համակարգչի վրա (CPU, Apple MPS կամ NVIDIA CUDA) և փորձերի վերարտադրելիություն։


# ԳԼՈՒԽ 1. ԵՐԹԵՎԵԿՈՒԹՅԱՆ ՀՈՍՔԻ ՎԵՐԼՈՒԾՈՒԹՅԱՆ ՏԵԽՆՈԼՈԳԻԱՆԵՐԸ

## 1.1. ԵՐԹԵՎԵԿՈՒԹՅԱՆ ՀՈՍՔԻ ԲՆՈՒԹԱԳՐԵՐԸ ԵՎ ՏՎՅԱԼՆԵՐԻ ՀԱՎԱՔՄԱՆ ԵՂԱՆԱԿՆԵՐԸ

### Երթևեկության հոսքի բնութագրերը

Երթևեկության տեսության մեջ հոսքը նկարագրվում է երեք հիմնական մակրոսկոպիկ մեծություններով՝ ինտենսիվությամբ, խտությամբ և միջին արագությամբ [10, 11, 21]։

**Ինտենսիվությունը** (q) ժամանակի միավորում ճանապարհի հատույթով անցնող տրանսպորտային միջոցների քանակն է։ Եթե T վայրկյան տևողությամբ դիտարկման ընթացքում հատույթով անցել է N մեքենա, ապա

> q = N · 3600 / T,  մեքենա/ժամ  (1.1)

**Խտությունը** (k) ճանապարհի միավոր երկարության վրա միաժամանակ գտնվող մեքենաների քանակն է։ L մետր երկարությամբ գոտում n մեքենայի դեպքում

> k = n / (L / 1000),  մեքենա/կմ  (1.2)

Բազմագոտի ճանապարհի համար օգտագործվում է նաև խտությունը մեկ երթևեկության գոտու համար՝ k / m, որտեղ m-ը գոտիների քանակն է։

**Միջին արագությունը** սահմանվում է երկու եղանակով։ Ժամանակային միջին արագությունը (time-mean speed) հատույթով անցնող մեքենաների արագությունների թվաբանական միջինն է։ Տարածական միջին արագությունը (space-mean speed) տվյալ պահին ճանապարհի հատվածում գտնվող մեքենաների միջին արագությունն է. հատույթում չափված n կետային արագությունների դեպքում այն գնահատվում է հարմոնիկ միջինով՝

> v_s = n / Σ (1 / v_i)  (1.3)

Տարածական միջին արագությունը միշտ փոքր կամ հավասար է ժամանակային միջինից, քանի որ դանդաղ մեքենաները ավելի երկար են մնում հատվածում։ Հենց v_s-ն է մասնակցում հոսքի հիմնական հավասարմանը՝

> q = k · v_s  (1.4)

Այս առնչությունը ծրագրում օգտագործվում է որպես ներքին համաձայնության ստուգում. եթե չափված q-ն էապես տարբերվում է k·v_s արտադրյալից, ապա խախտված է չափման որևէ ենթադրություն (սխալ տրամաչափում, կրկնակի հաշվարկ կամ արագացված տեսանյութ)։

**Սպասարկման մակարդակը** (Level of Service, LOS) հոսքի որակի որակական գնահատական է՝ A (ազատ երթևեկություն) մինչև F (խցանում)։ Highway Capacity Manual (HCM) ձեռնարկում մայրուղու հիմնական հատվածի համար LOS-ը որոշվում է խտությամբ՝ մեկ գոտու համար [10]։ Ծրագրում օգտագործվում են HCM շեմերը՝ փոխարկված մեքենա/կմ/գոտի միավորների (աղյուսակ 1.1)։

Աղյուսակ 1.1 Սպասարկման մակարդակը ըստ խտության (HCM, մայրուղու հիմնական հատված)

| LOS | Խտություն, մարդատար ավտ./մղոն/գոտի | Խտություն, մեքենա/կմ/գոտի | Բնութագիր |
|:---:|---:|---:|---|
| A | ≤ 11 | ≤ 7 | Ազատ երթևեկություն |
| B | ≤ 18 | ≤ 11 | Մոտ ազատ երթևեկություն |
| C | ≤ 26 | ≤ 16 | Կայուն հոսք |
| D | ≤ 35 | ≤ 22 | Մոտ անկայուն հոսք |
| E | ≤ 45 | ≤ 28 | Թողունակության սահման |
| F | > 45 | > 28 | Խցանում |

HCM-ը նաև սահմանում է մայրուղու մեկ գոտու թողունակությունը՝ մոտ 2400 մարդատար ավտոմեքենա/ժամ։ Ծրագրում այս արժեքը օգտագործվում է որպես վերին սահման. մեկ գոտու համար ավելի մեծ չափված ինտենսիվությունը ցույց է տալիս սխալ (օրինակ՝ արագացված տեսանյութ)։

Պետք է նշել, որ HCM-ի շեմերը սահմանված են մարդատար ավտոմեքենայի համարժեքով (բեռնատարը և ավտոբուսը հաշվվում են մեկից ավելի միավոր)։ Ծրագրում խտությունը հաշվվում է ֆիզիկական մեքենաներով, ուստի ծանր տրանսպորտի մեծ բաժնի դեպքում LOS-ը կարող է մի փոքր լավատեսական լինել։

### Երթևեկության տվյալների հավաքման եղանակները

Երթևեկության տվյալները հավաքվում են տարբեր սենսորներով (աղյուսակ 1.2)։ Ինդուկտիվ օղակները ճշգրիտ հաշվում են մեքենաները, սակայն տեղադրվում են ճանապարհի ծածկույթի մեջ և չափում են միայն մեկ կետում։ Ռադարները և լազերային սենսորները լավ չափում են արագությունը, բայց վատ են տարբերակում դասերը և մոտ մեքենաները։ Տեսախցիկը տալիս է ամենահարուստ տեղեկությունը՝ դաս, հետագիծ, ուղղություն, գոտի և խտություն մեկ սարքով, իսկ բազմաթիվ քաղաքներում տեսախցիկներն արդեն տեղադրված են։ Տեսանյութի թերությունները զգայունությունն են լուսավորության, եղանակի և ծածկումների նկատմամբ, ինչպես նաև հաշվողական պահանջները։

Աղյուսակ 1.2 Երթևեկության տվյալների հավաքման եղանակների համեմատություն

| Եղանակ | Հաշվարկ | Արագություն | Դաս | Խտություն, հետագծեր | Տեղադրում |
|---|---|---|---|---|---|
| Ձեռքով հաշվարկ | Այո | Ոչ | Այո | Ոչ | Աշխատատար, կարճատև |
| Ինդուկտիվ օղակ | Այո | Զույգ օղակով | Երկարությամբ | Ոչ | Ճանապարհային աշխատանքներ |
| Ռադար, լիդար | Այո | Այո | Սահմանափակ | Մասամբ | Սյան վրա |
| Տեսախցիկ + CNN | Այո | Տրամաչափմամբ | Այո | Այո | Սյան վրա, հաճախ արդեն առկա |

## 1.2. ՓԱԹՈՒՅԹԱՅԻՆ ՆԵՅՐՈՆԱՅԻՆ ՑԱՆՑԵՐԸ ԵՎ YOLOv8 ԴԵՏԵԿՏՈՐԸ

### Փաթույթային նեյրոնային ցանցեր և օբյեկտների հայտնաբերում

Փաթույթային նեյրոնային ցանցը կազմված է շերտերից, որոնցից յուրաքանչյուրը պատկերի կամ նախորդ շերտի հատկանիշների քարտեզի վրա կիրառում է ուսուցանվող փոքր ֆիլտրեր (փաթույթի միջուկներ)։ Ֆիլտրի կշիռները ընդհանուր են պատկերի բոլոր դիրքերի համար, ինչը կտրուկ նվազեցնում է պարամետրերի քանակը և ապահովում է տեղաշարժի նկատմամբ կայունություն։ Առաջին շերտերը սովորում են պարզ հատկանիշներ (եզրեր, գույնի անցումներ), իսկ խորը շերտերը՝ բարդ ձևեր (անիվներ, պատուհաններ, ամբողջ մեքենաներ)։ Ոչ գծային ակտիվացման ֆունկցիաները, նորմավորումը և քայլով փաթույթները կամ միավորումը (pooling) աստիճանաբար նվազեցնում են տարածական չափը և մեծացնում են ընկալման դաշտը։

Օբյեկտների հայտնաբերման խնդրում ցանցը պետք է պատկերի յուրաքանչյուր օբյեկտի համար որոշի սահմանափակող շրջանակը (x₁, y₁, x₂, y₂), դասը և վստահությունը։ Հայտնաբերման մեթոդները բաժանվում են երկու խմբի։ Երկփուլանի մեթոդները (R-CNN, Faster R-CNN [15]) նախ առաջարկում են թեկնածու տիրույթներ, ապա դասակարգում են դրանք. դրանք ճշգրիտ են, բայց դանդաղ։ Մեկփուլանի մեթոդները (SSD, RetinaNet, YOLO ընտանիք [14]) մեկ անցումով կանխատեսում են շրջանակները և դասերը հատկանիշների քարտեզի բոլոր դիրքերում, ինչը թույլ է տալիս մշակել տեսանյութն իրական ժամանակում։

Կանխատեսված և իրական շրջանակների համընկնումը չափվում է IoU (Intersection over Union) մեծությամբ՝

> IoU(A, B) = |A ∩ B| / |A ∪ B|  (1.5)

Հայտնաբերումը համարվում է ճիշտ (true positive), եթե դասը համընկնում է, իսկ IoU-ն շեմից բարձր է։ Նույն օբյեկտի կրկնվող շրջանակները հեռացվում են ոչ-մաքսիմալ ճնշմամբ (NMS). պահպանվում է ամենավստահ շրջանակը, իսկ դրա հետ բարձր IoU ունեցողները հեռացվում են։ Որակի հիմնական չափանիշը միջին ճշտությունն է (AP)՝ precision-recall կորի տակ ընկած մակերեսը, իսկ mAP-ը AP-ի միջինն է բոլոր դասերով։ mAP50-ը հաշվվում է IoU = 0,5 շեմով, իսկ mAP50–95-ը՝ 0,50-ից 0,95 շեմերով 0,05 քայլով միջինացված (ավելի խիստ չափանիշ շրջանակի ճշտության համար)։

### YOLOv8 ճարտարապետությունը

Աշխատանքում օգտագործվում է Ultralytics ընկերության YOLOv8 դետեկտորը [3]։ Այն բաղկացած է երեք մասից.

- **հիմնական ցանց (backbone)**՝ CSPDarknet տիպի փաթույթային ցանց C2f բլոկներով, որը կառուցում է հատկանիշների քարտեզներ 8, 16 և 32 քայլերով (stride).
- **պարանոց (neck)**՝ PAN-FPN կառուցվածք [17], որը միավորում է տարբեր մասշտաբների հատկանիշները վերից վար և վարից վեր ուղղություններով. դա կարևոր է միաժամանակ փոքր (հեռավոր) և մեծ (մոտիկ) մեքենաներ հայտնաբերելու համար.
- **գլուխ (head)**՝ առանց խարիսխ-շրջանակների (anchor-free) և բաժանված (decoupled) ճյուղերով դասակարգման և շրջանակի ռեգրեսիայի համար։

Ուսուցման ընթացքում օգտագործվում են դասակարգման կորստի ֆունկցիան (երկուական խաչաձև էնտրոպիա), շրջանակի կորուստը (CIoU) և բաշխման ֆոկալ կորուստը (DFL)։ Ultralytics գրադարանը ներառում է նաև տվյալների ընդլայնման ստանդարտ եղանակներ՝ մոզաիկա, մասշտաբավորում, հայելային արտապատկերում, գույնի փոփոխություն։

YOLOv8-ը հասանելի է մի քանի չափերով, որոնք տարբերվում են ցանցի խորությամբ և լայնությամբ։ Աշխատանքում օգտագործվել են երկու ամենափոքրը (աղյուսակ 1.3)։ YOLOv8n-ը (nano) հարմար է թույլ համակարգիչների համար, YOLOv8s-ը (small) մոտ 3,5 անգամ ավելի շատ պարամետր ունի և ավելի ճշգրիտ է։

Աղյուսակ 1.3 Օգտագործված YOLOv8 մոդելների բնութագրերը (COCO, 640 պքս, ըստ Ultralytics-ի [3])

| Մոդել | Պարամետրեր, մլն | Հաշվարկ, GFLOPs | COCO mAP50–95 |
|---|---:|---:|---:|
| YOLOv8n | 3,2 | 8,7 | 37,3% |
| YOLOv8s | 11,2 | 28,6 | 44,9% |

YOLOv8-ի ընտրությունը պայմանավորված է հետևյալով. մեկփուլանի դետեկտորը ապահովում է իրական ժամանակին մոտ արագություն առանց մասնագիտացված GPU-ի (Apple Silicon-ի MPS, CUDA կամ CPU), գրադարանը ներառում է ուսուցում, գնահատում և հետագծում միասնական միջերեսով, իսկ COCO հավաքածուով նախնական ուսուցանված կշիռները թույլ են տալիս կիրառել ուսուցման փոխանցում։

![Նկ. 1.1. YOLOv8 դետեկտորի կառուցվածքի սխեման](reports/thesis/yolov8-hy.png)

### Զրոյից ուսուցում և ուսուցման փոխանցում

Ժամանակակից դետեկտորն ունի միլիոնավոր պարամետրեր, և դրա զրոյից ուսուցումը պահանջում է մեծ նշագրված հավաքածու և երկար ուսուցում։ Ուսուցման փոխանցման դեպքում ցանցի սկզբնական կշիռները վերցվում են մեծ ընդհանուր հավաքածուով (COCO [16], 80 դաս, այդ թվում car, truck, bus, motorcycle) ուսուցանված մոդելից, իսկ այնուհետև ցանցը լրացուցիչ ուսուցանվում է թիրախային տվյալներով։ Ցածր մակարդակի հատկանիշները (եզրեր, հյուսվածքներ) ընդհանուր են տարբեր խնդիրների համար, ուստի լրացուցիչ ուսուցումը ավելի արագ է զուգամիտում և ավելի լավ է ընդհանրացնում փոքր հավաքածուի վրա։ Աշխատանքի 2-րդ գլխում երկու եղանակները համեմատված են նույն տվյալներով և նույն բյուջեով։

Ուսուցման փոխանցման կարևոր հարց է **տիրույթի տեղաշարժը** (domain shift)։ Անօդաչու սարքից արված պատկերներում մեքենաները փոքր են և երևում են վերևից, իսկ ճանապարհային տեսախցիկում՝ թեք անկյան տակ և ավելի մեծ։ Մեկ տիրույթում ուսուցանված մոդելը կարող է վատ աշխատել մյուսում, ինչը փորձարարականորեն հաստատված է 2.3 բաժնում։

## 1.3. ՀԵՏԱԳԾՄԱՆ ԵՎ ՏՐԱՄԱՉԱՓՄԱՆ ՄԵԹՈԴՆԵՐԸ

### Բազմաօբյեկտային հետագծում և ByteTrack

Բազմաօբյեկտային հետագծման (Multi-Object Tracking, MOT) խնդիրն է հաջորդական կադրերի հայտնաբերումները միավորել հետագծերի, որոնցից յուրաքանչյուրը ստանում է կայուն նույնացուցիչ (ID)։ «Հետագծում հայտնաբերման միջոցով» (tracking-by-detection) մոտեցման դեպքում յուրաքանչյուր հետագծի համար Կալմանի ֆիլտրով կանխատեսվում է (SORT ալգորիթմ [19]) շրջանակի դիրքը հաջորդ կադրում, ապա կանխատեսումները համապատասխանեցվում են նոր հայտնաբերումներին IoU-ի հիման վրա՝ Հունգարական ալգորիթմով։

ByteTrack ալգորիթմի [4] հիմնական գաղափարն այն է, որ ցածր վստահությամբ հայտնաբերումները չեն անտեսվում։ Համապատասխանեցումը կատարվում է երկու փուլով. սկզբում բարձր վստահությամբ շրջանակները համապատասխանեցվում են բոլոր հետագծերին, ապա մնացած հետագծերը փորձում են գտնել իրենց շարունակությունը ցածր վստահությամբ շրջանակների մեջ։ Մասամբ ծածկված մեքենան հաճախ հայտնաբերվում է ցածր վստահությամբ, և այս երկրորդ փուլը թույլ է տալիս չկորցնել դրա հետագիծը։ Նոր հետագիծ ստեղծվում է միայն բարձր վստահությամբ հայտնաբերումից, իսկ կորած հետագիծը պահվում է որոշ թվով կադրեր՝ հնարավոր վերադարձի համար։

Հետագծման հիմնական սխալներն են ID-ի փոխարկումը (նույն մեքենան ստանում է նոր ID), երկու մեքենաների ID-ների փոխանակումը և հետագծի կորուստը։ Հաշվարկի համար ամենավտանգավորը ID-ի փոխարկումն է, քանի որ այն կարող է հանգեցնել նույն մեքենայի կրկնակի հաշվարկի։ Աշխատանքում մշակված պաշտպանական մեխանիզմները նկարագրված են 3.1 բաժնում։

### Պատկերի և ճանապարհի հարթության կապը

Արագությունը և խտությունը պահանջում են իրական չափեր մետրերով, իսկ տեսախցիկը տալիս է պիքսելային կոորդինատներ։ Հեռանկարի պատճառով նույն 1 մետրը կադրի ներքևում զբաղեցնում է շատ ավելի պիքսելներ, քան վերևում։ Եթե ճանապարհը հարթ է, ապա պատկերի հարթության (x, y) և ճանապարհի հարթության (X, Y) կետերի միջև կապը նկարագրվում է պրոյեկտիվ ձևափոխությամբ՝ հոմոգրաֆիայով [9].

> s · [X, Y, 1]ᵀ = H · [x, y, 1]ᵀ  (1.6)

որտեղ H-ը 3×3 մատրից է՝ 8 ազատության աստիճանով, իսկ s-ը մասշտաբային գործակից է։ H-ը որոշելու համար բավարար է չորս կետերի համապատասխանություն, որոնցից ոչ մի երեքը չեն գտնվում նույն ուղղի վրա. օրինակ՝ ճանապարհի վրա հայտնի չափերով ուղղանկյան չորս անկյունները։ Յուրաքանչյուր զույգ տալիս է երկու գծային հավասարում, և համակարգը լուծվում է ուղիղ գծային ձևափոխության (DLT) մեթոդով՝ եզակի արժեքների վերլուծությամբ (SVD)։

Մեքենայի հենակետ է ընտրվում շրջանակի ստորին եզրի միջնակետը, որը մոտավորապես համընկնում է մեքենայի և ճանապարհի հպման կետի հետ։ Այդ կետը H-ով ձևափոխելով՝ ստացվում է մեքենայի դիրքը ճանապարհի վրա մետրերով, իսկ դիրքի փոփոխությունը ժամանակի ընթացքում տալիս է արագությունը։ Մեթոդի ենթադրություններն են հարթ ճանապարհը, անշարժ տեսախցիկը և ճիշտ տրամաչափման կետերը։ Տրամաչափման մասշտաբի սխալը համամասնորեն փոխում է բոլոր արագությունները։

# ԳԼՈՒԽ 2. ՏՎՅԱԼՆԵՐԻ ՊԱՏՐԱՍՏՈՒՄԸ ԵՎ CNN-Ի ՈՒՍՈՒՑՄԱՆ ՓՈՐՁԵՐԻ ՎԵՐԼՈՒԾՈՒԹՅՈՒՆԸ

## 2.1. ՈՒՍՈՒՑՄԱՆ ՏՎՅԱԼՆԵՐԻ ՊԱՏՐԱՍՏՈՒՄԸ

### Տվյալների աղբյուրներ և թիրախային դասեր

CNN դետեկտորի ուսուցման համար անհրաժեշտ են պատկերներ, որոնցում յուրաքանչյուր տրանսպորտային միջոց նշագրված է շրջանակով և դասով։ Աշխատանքում օգտագործվել են երեք բաց հավաքածուներ, որոնք լրացնում են միմյանց (աղյուսակ 2.1)։

Աղյուսակ 2.1 Օգտագործված հավաքածուները

| Հավաքածու | Նկարահանում | Կիրառում աշխատանքում | Լիցենզիա |
|---|---|---|---|
| VisDrone2019-DET [1, 2] | Անօդաչու սարք, 14 քաղաք, տարբեր բարձրություններ | Ուսուցում, ստուգում, թեստ | Ակադեմիական օգտագործում |
| MIO-TCD Localization [12] | Անշարժ ճանապարհային տեսախցիկներ (Կանադա, ԱՄՆ) | Ուսուցում, ստուգում, թեստ | CC BY-NC-SA 4.0 |
| UA-DETRAC [13] | Ճանապարհային տեսախցիկներ (Պեկին, Տյանցզին) | Միայն արտաքին ստուգում | Ակադեմիական օգտագործում |

Ընտրվել են հինգ թիրախային դասեր, որոնք կարևոր են երթևեկության վերլուծության համար և առկա են բոլոր աղբյուրներում՝ **car** (մարդատար ավտոմեքենա), **van** (միկրոավտոբուս, ֆուրգոն), **truck** (բեռնատար), **bus** (ավտոբուս), **motorcycle** (մոտոցիկլ)։ Հետիոտները, հեծանիվները և եռանիվները թիրախային չեն և նշագրությունից հեռացվել են։

### VisDrone2019-DET հավաքածուի պատրաստումը

VisDrone2019-DET-ը բաղկացած է անօդաչու սարքից արված պատկերներից՝ պաշտոնական train, val և test-dev բաժանմամբ [8]։ Աղբյուրի արխիվները ներբեռնվում են `scripts/download_data.py` սկրիպտով և ստուգվում են SHA-256 հեշով։ `scripts/prepare_visdrone.py` սկրիպտը կատարում է հետևյալ քայլերը.

1. կարդում է VisDrone-ի նշագրությունը (շրջանակ՝ ձախ վերին անկյուն, լայնություն, բարձրություն, գնահատման դրոշակ, դաս).
2. վերածում է դասերը թիրախային հինգ դասերի (car → car, van → van, truck → truck, bus → bus, motor → motorcycle), իսկ մնացածը բաց է թողնում.
3. բաց է թողնում «անտեսվող տիրույթները» (դրոշակ 0) և անվավեր շրջանակները.
4. փոխակերպում է շրջանակները YOLO ձևաչափի՝ կենտրոն և չափեր, նորմավորված պատկերի չափերով.
5. հաշվում է յուրաքանչյուր պատկերի SHA-256 հեշը և հեռացնում է ճշգրիտ կրկնօրինակները.
6. պահպանում է մանիֆեստ (`reports/dataset.json`)՝ աղբյուրների հեշերով, դասերի վիճակագրությամբ և սահմանափակումներով։

Գտնվել և հեռացվել են երեք ճշգրիտ կրկնօրինակներ (երկուսը train-ում, մեկը val-ում)։ Պատրաստված հավաքածուի կազմը ներկայացված է աղյուսակ 2.2-ում։

Աղյուսակ 2.2 VisDrone հավաքածուն պատրաստումից հետո (շրջանակների քանակ ըստ դասերի)

|---|---:|---:|---:|---:|---:|---:|---:|

![Նկ. 2.1. Շրջանակների բաշխումն ըստ դասերի (VisDrone, ամբողջ train)](reports/class-distribution-full.png)

Հավաքածուն խիստ անհավասարակշիռ է. մարդատար ավտոմեքենաները կազմում են շրջանակների 66%-ը, իսկ ավտոբուսները՝ ընդամենը 2,7%-ը։ Դա հանգեցնում է նրան, որ հազվադեպ դասերի (van, bus, motorcycle) հայտնաբերման ճշտությունը զգալիորեն ցածր է (տե՛ս 2.3 բաժինը)։ Երթևեկության հաշվարկի համար այս սահմանափակումը մասամբ մեղմվում է նրանով, որ հաշվարկը կատարվում է բոլոր դասերի համար միասին, իսկ դասի սխալը չի փոխում ընդհանուր քանակը։

Փորձերի համար առանձնացվել է նաև **փորձնական ենթաընտրանք**՝ 1024 պատկեր train-ից (seed 42, հավասարաչափ ընտրություն ֆայլերի անվան նախածանցներով), իսկ val և test ընտրանքները պահպանվել են ամբողջությամբ։

VisDrone-ի պաշտոնական գնահատումը դիմակավորում է անտեսվող տիրույթները։ Աշխատանքում դրանք պարզապես բաց են թողնված նշագրությունից, ուստի ստացված mAP-ը պաշտոնական VisDrone գնահատական չէ և համեմատելի է միայն այս աշխատանքի տարբեր մոդելների միջև։

### Տվյալների ընդլայնում

Ուսուցման հավաքածուն ընդլայնելու համար `scripts/expand_training.py` սկրիպտը ստեղծում է 1024 լրացուցիչ տարբերակ՝ հայելային արտապատկերմամբ (շրջանակների ճիշտ վերահաշվարկով), պայծառության և կոնտրաստի փոփոխությամբ և թեթև գաուսյան լղոզմամբ (յուրաքանչյուր երրորդ պատկերի համար)։ Ընդլայնված ցուցակը (`configs/visdrone-expanded-full.yaml`) պարունակում է 7493 ուսուցման ֆայլ։ Val և test ընտրանքները չեն փոփոխվում։ Պետք է նշել, որ ընդլայնումը նոր անկախ տեսարաններ չի ավելացնում, այլ միայն փոփոխում է առկաները։

![Նկ. 2.2. Ընդլայնված ուսուցման պատկերների օրինակներ](reports/training-augmentation-preview.png)

### MIO-TCD հավաքածուի ավելացումը

VisDrone-ի հիմնական թերությունը վերևից դիտման անկյունն է, որը տարբերվում է ճանապարհային տեսախցիկից։ Այդ տիրույթի տեղաշարժը նվազեցնելու համար ավելացվել է MIO-TCD Localization հավաքածուն [12], որը պարունակում է մոտ 110 հազար պատկեր անշարժ ճանապարհային տեսախցիկներից՝ տարբեր եղանակային պայմաններում և օրվա տարբեր ժամերի։

`scripts/prepare_miotcd.py` սկրիպտը վերածում է MIO-TCD-ի 11 դասերը թիրախային դասերի (աղյուսակ 2.3)։ MIO-TCD-ում կա «motorized_vehicle» դասը, որը նշանակում է անորոշ տեսակի մոտորացված միջոց։ Այն չի կարելի վերագրել որևէ թիրախային դասի, բայց չի կարելի նաև համարել ֆոն, քանի որ դա կսովորեցնի ցանցին չհայտնաբերել իրական մեքենաներ։ Ուստի այդ շրջանակների տիրույթները պատկերում **դիմակավորվում են** (ներկվում են տվյալ պատկերի միջին գույնով)։

Աղյուսակ 2.3 MIO-TCD դասերի համապատասխանեցումը

| MIO-TCD դաս | Թիրախային դաս |
|---|---|
| car, pickup_truck | car |
| work_van | van |
| articulated_truck, single_unit_truck | truck |
| bus | bus |
| motorcycle | motorcycle |
| motorized_vehicle | դիմակավորվում է |
| pedestrian, bicycle, non-motorized_vehicle | բաց է թողնվում |

MIO-TCD-ն չունի պաշտոնական թեստային նշագրություն, ուստի բաժանումը կատարվել է դետերմինիստիկ կանոնով՝ պատկերի նույնացուցիչի SHA-256 հեշով. 85% train, 5% val, 10% test։ Ուսուցման ժամանակը սահմանափակելու համար train-ից օգտագործվել է 30 000 պատկերի պատահական ենթաընտրանք։

## 2.2. ՍՏՈՒԳՄԱՆ ՏՎՅԱԼՆԵՐԸ ԵՎ ԳՆԱՀԱՏՄԱՆ ՄԵԹՈԴԻԿԱՆ

### UA-DETRAC արտաքին ստուգման համար

UA-DETRAC-ը [13] պարունակում է ճանապարհային տեսախցիկների տեսահաջորդականություններ (25 կադր/վ, 960×540)՝ յուրաքանչյուր մեքենայի հրապարակված հետագծով (նույն ID բոլոր կադրերում)։ Այն **չի օգտագործվել ուսուցման համար** և ծառայում է որպես անկախ ստուգում ինչպես հայտնաբերման, այնպես էլ հաշվարկի համար։

Ստուգման համար նախապես (մինչև արդյունքները տեսնելը) ընտրվել են թեստային բաժնի առաջին երեք հաջորդականությունները՝ անվանման կարգով, յուրաքանչյուրից առաջին 300 կադրը (12 վայրկյան)։ Հեղինակի Google Drive արխիվի ներբեռնման քվոտայի սահմանափակման պատճառով հաջողվել է ստանալ միայն MVI_39031 հաջորդականությունը։ Դրանում 300 կադրում կա 523 նշագրված շրջանակ։ Հաշվման գիծը նախապես ֆիքսվել է կադրի բարձրության 60%-ի վրա, և հրապարակված հետագծերից ավտոմատ ստացվել են 5 հատման իրադարձություններ (4 car, 1 van)։ Հրապարակված անտեսվող տիրույթները հեռացվում են հայտնաբերման գնահատման ժամանակ։

### Ցուցադրական տեսանյութեր

Ծրագրի ամբողջական ստուգման համար օգտագործվել են Roboflow Supervision գրադարանի երկու բաց ցուցադրական տեսանյութեր [6].

- **vehicles.mp4** (տեսանյութ 1)՝ մայրուղի, 3840×2160, 25 կադր/վ, 21,52 վ, 538 կադր, երկու ուղղությամբ երթևեկություն.
- **vehicles-2.mp4** (տեսանյութ 2)՝ մայրուղի, 1920×1080, 29,97 կադր/վ, 42,54 վ, 1275 կադր, խիտ հոսք։

Տեսանյութ 1-ի համար մինչև մոդելների կանխատեսումները դիտելը պատրաստվել է նախնական նշագրում՝ 10 հատում (7 դեպի կադրի ստորին եզր, 3 դեպի վերին եզր, 8 car, 2 truck)։ Այս նշագրումը կատարվել է կադրերի ակնարկային թերթերով և պահանջում է անկախ ստուգում մարդու կողմից։ Քանի որ այս տեսանյութն օգտագործվել է հաշվման կանոնների մշակման ժամանակ, դրա արդյունքները մշակման օրինակ են, ոչ թե անկախ թեստ։ Տեսանյութ 2-ը նշագրում չունի և օգտագործվում է ծրագրի վարքագծի և հավաստիության ստուգման համար (3.3 բաժին)։

### Փորձերի կազմակերպումը

Բոլոր ուսուցման փորձերը կատարվել են մեկ համակարգչի վրա (Apple MacBook, M4 պրոցեսոր, 16 ԳԲ հիշողություն, PyTorch MPS սարք)՝ միևնույն ֆիքսված պատահական seed-ով (42)։ Յուրաքանչյուր փորձ գործարկվում է `scripts/run_experiment.py` սկրիպտով, որն օգտագործում է Ultralytics-ի ուսուցման ռեժիմը [7] և.

- պահպանում է ուսուցման բոլոր պարամետրերը (`args.yaml`), գրադարանների տարբերակները և ուսուցման ժամանակը.
- ընտրում է լավագույն դարաշրջանը (epoch) միայն ստուգողական (val) ընտրանքով, ոչ թե թեստայինով.
- գնահատում է ընտրված կշիռները թեստային ընտրանքում մեկ անգամ.
- պահպանում է ամփոփ ցուցանիշները և ըստ դասերի ցուցանիշները JSON ֆայլում (`reports/vehicle-*.json`)։

Պարամետրերի ընտրությունը (մուտքի չափ, սալիկի չափ, լավագույն մոդել) կատարվել է val ընտրանքով, իսկ թեստային արդյունքները օգտագործվել են միայն նկարագրության համար։ Այնուամենայնիվ, պետք է նշել, որ նույն թեստային ընտրանքը հաշվետվություններում օգտագործվել է բազմաթիվ անգամներ, ուստի այն չի կարող համարվել լիովին «կույր»։ Հենց դրա համար կարևոր է արտաքին UA-DETRAC ստուգումը։

MPS սարքի որոշ գործողություններ դետերմինիստիկ չեն, ուստի նույն փորձի կրկնությունը կարող է տալ մի փոքր տարբեր արդյունքներ։ Յուրաքանչյուր կոնֆիգուրացիա ուսուցանվել է մեկ անգամ, ուստի տարբերությունների վիճակագրական նշանակալիությունը չի գնահատվել. փոքր (1 տոկոսային կետից պակաս) տարբերությունները պետք է մեկնաբանել զգուշությամբ։

### Հայտնաբերման գնահատում

Հայտնաբերման որակը գնահատվում է ստանդարտ ցուցանիշներով.

- **precision** (ճշտություն)՝ ճիշտ հայտնաբերումների բաժինը բոլոր հայտնաբերումներում.
- **recall** (լրիվություն)՝ հայտնաբերված իրական օբյեկտների բաժինը.
- **mAP50**՝ միջին ճշտությունը IoU ≥ 0,5 շեմով, միջինացված հինգ դասերով.
- **mAP50–95**՝ միջին ճշտությունը IoU 0,50–0,95 շեմերով։

Հիմնական աղյուսակներում օգտագործվում է Ultralytics գրադարանի ստանդարտ գնահատիչը։ Սալիկային հայտնաբերման համար գրվել է սեփական գնահատիչ (`scripts/evaluate_tiled.py`), քանի որ գրադարանի գնահատիչը չի աջակցում սալիկներին։ Այն օգտագործում է յուրաքանչյուր շրջանակի համար մեկ դաս (ինչպես ծրագրում), մինչդեռ գրադարանի գնահատիչը թույլ է տալիս մի քանի դաս մեկ շրջանակի համար և տալիս է մոտ 3–4 կետով բարձր թվեր։ Ուստի համեմատվում են միայն նույն գնահատիչով ստացված թվերը։

UA-DETRAC-ում հայտնաբերումը գնահատվում է առանց դասերի տարբերակման («տրանսպորտային միջոց» մեկ դաս), քանի որ UA-DETRAC-ի դասերը (car, bus, van, others) չեն համընկնում թիրախային դասերի հետ։ Հրապարակված անտեսվող տիրույթներում կենտրոն ունեցող շրջանակները հեռացվում են։ Կիրառվում է ագահ համապատասխանեցում IoU-ով յուրաքանչյուր կադրում և precision-ի 101 կետանոց ինտերպոլյացիա։ Սա սեփական արձանագրություն է, ոչ թե UA-DETRAC-ի պաշտոնական գնահատական։

### Հաշվարկի գնահատում

Հայտնաբերման բարձր mAP-ը չի երաշխավորում ճիշտ հաշվարկ. մեկ բաց թողնված կադրը կարող է չազդել mAP-ի վրա, բայց ID-ի փոխարկումը կրկնակի կհաշվի մեքենան։ Ուստի հաշվարկը գնահատվում է առանձին՝ իրադարձությունների մակարդակում։

Էտալոնային նշագրումը պարունակում է յուրաքանչյուր իրական հատման համար կադրերի միջակայքը, ուղղությունը և դասը։ Ծրագրի գրանցած յուրաքանչյուր հատում համապատասխանեցվում է էտալոնի ոչ ավելի, քան մեկ իրադարձության, եթե ուղղությունները համընկնում են, իսկ հատման կադրը ընկած է էտալոնային միջակայքում՝ 6 կադր թույլատրելի շեղումով (`scripts/evaluate_counting.py`)։ Համապատասխանեցումից հետո հաշվվում են.

- համընկած իրադարձությունները (TP), բաց թողնվածները (FN) և ավելորդները (FP).
- իրադարձությունների precision = TP / (TP + FP), recall = TP / (TP + FN) և F1.
- դասի անհամապատասխանությունները համընկած զույգերում։

Այս մոտեցումը բացահայտում է այն սխալները, որոնք թաքնված են ընդհանուր քանակի համեմատության ժամանակ։ Օրինակ, եթե ծրագիրը բաց է թողել մեկ մեքենա և կրկնակի հաշվել մյուսը, ընդհանուր քանակը ճիշտ կլինի, բայց F1-ը՝ 90%։

Գնահատումը թույլատրվում է միայն այն դեպքում, երբ արդյունքի և էտալոնի տեսանյութի SHA-256 հեշը, FPS-ը և հաշվման գծի կոորդինատները համընկնում են։ Միջերեսում հնարավոր է ստեղծել սեփական նշագրում կադր առ կադր (3.2 բաժին)։

### Արագության ստուգում

Ցուցադրական տեսանյութերի համար անկախ չափված (ռադարով կամ GPS-ով) արագություններ հասանելի չեն, ուստի արագության բացարձակ ճշտությունը հնարավոր չէ գնահատել։ Կատարվում են երկու ստուգում.

1. **Ներքին համաձայնություն երկու գծով։** Տեսանյութ 1-ում սահմանվում են երկու զուգահեռ հաշվման գծեր։ Յուրաքանչյուր մեքենայի համար, որը հատել է երկու գծերը, արագությունը հաշվվում է անկախ եղանակով՝ գծերի միջև ճանապարհային հեռավորությունը (մետրերով) բաժանած անցման ժամանակի վրա, և համեմատվում է սահող պատուհանով գնահատված մեդիան արագության հետ։ Սա ստուգում է արագության գնահատիչի կայունությունը, բայց ոչ տրամաչափման ճշտությունը, քանի որ երկու եղանակներն էլ օգտագործում են նույն հոմոգրաֆիան։
2. **Ֆիզիկական հավաստիություն։** Ստուգվում է, որ արագությունները համապատասխանում են ճանապարհի տեսակին, իսկ q = k·v_s հավասարումը բավարարվում է (3.1 բաժին)։

Տեսանյութ 1-ի տրամաչափումը վերցված է Roboflow Supervision գրադարանի արագության գնահատման օրինակից (ճանապարհի 25 մ լայնությամբ և 250 մ երկարությամբ ուղղանկյուն, 4 գոտի)։ Տեսանյութ 2-ի տրամաչափումը կատարվել է հեղինակի կողմից՝ ընդհատվող գծանշման պարբերությամբ (3 մ գիծ + 9 մ բացվածք = 12 մ, 10 պարբերություն = 120 մ) և 3,6 մ գոտու ենթադրյալ լայնությամբ։ Երկու տրամաչափումներն էլ մոտավոր են և չափված չեն տեղում։

### Արագագործության չափում

Մշակման արագությունը չափվում է որպես մշակված կադրերի քանակը բաժանած ամբողջ մշակման ժամանակի վրա (`processing_fps`)՝ ներառյալ տեսանյութի ապակոդավորումը, հայտնաբերումը, հետագծումը, նշագրված տեսանյութի գրառումը և CSV ֆայլերի գրառումը։ Այն կախված է տեսանյութի լուծաչափից, մոդելից, մուտքի չափից, տրամաչափման և գծերի քանակից, ինչպես նաև համակարգչի ընթացիկ բեռնվածությունից։ Մոդելների զուտ հայտնաբերման ժամանակը չափվում է առանձին՝ միլիվայրկյան մեկ պատկերի համար։

Արդյունքներից կարելի է անել հետևյալ եզրակացությունները։

**Ուսուցման փոխանցումը կարևոր է։** Նույն 1024 պատկերով և 15 դարաշրջանով զրոյից ուսուցանված մոդելը գրեթե չի սովորել (mAP50 2,6%, recall 3,8%), իսկ COCO կշիռներից սկսած մոդելը հասել է 13,8%-ի։ Սահմանափակ տվյալների և ժամանակի պայմաններում ուսուցման փոխանցումը միակ գործնական եղանակն է։

**Տվյալների ծավալը։** Ամբողջ train-ի (6469 պատկեր) և 640 պքս մուտքի օգտագործումը mAP50-ը բարձրացրել է մինչև 34,4%։ Այս փոփոխությունը միաժամանակ ներառում է տվյալների ծավալը և մուտքի չափը, ուստի ազդեցությունը չի կարելի վերագրել միայն մեկ գործոնի։

**Ընդլայնումը։** Հավասար բյուջեով (3 դարաշրջան, 2048 օրինակ դարաշրջանում) ընդլայնված տվյալներով մոդելը val mAP50–95-ում գերազանցել է ստուգիչ մոդելին ընդամենը 0,12 տոկոսային կետով, իսկ թեստում՝ զիջել 0,1 կետով։ Այս տարբերությունը չափման աղմուկի սահմաններում է. մեր կիրառած պարզ ընդլայնումը (արտապատկերում, պայծառություն, լղոզում) լրացուցիչ օգուտ չի տալիս, քանի որ Ultralytics-ն արդեն կիրառում է նմանատիպ ձևափոխություններ ուսուցման ժամանակ։

**Մուտքի չափը։** Ամենամեծ աճը տվել է մուտքի չափի մեծացումը 640-ից 960 պիքսել (34,7% → 45,9%)։ VisDrone-ում մեքենաները շատ փոքր են, և ավելի մեծ մուտքը պահպանում է դրանց մանրամասները (2.3 բաժին)։

**Երկարացված ուսուցումը։** vehicle-road-yolov8s մոդելի val ցուցանիշը 8-րդ դարաշրջանում դեռ աճում էր, ինչը նշանակում էր, որ մոդելը լիովին չէր սովորել։ Ուստի նրա լավագույն կշիռներից ուսուցումը շարունակվել է ևս 12 դարաշրջան՝ նույն տվյալներով և ավելի փոքր ուսուցման արագությամբ (lr0 = 0,0005)։ Առաջին դարաշրջանում val mAP50-ը ժամանակավորապես նվազել է (61,5% → 57,2%) ուսուցման արագության նախնական աճի (warm-up) պատճառով, որից հետո աճել է յուրաքանչյուր դարաշրջանից հետո՝ մինչև 65,2%։ Val mAP50–95-ը 44,3%-ից հասել է 47,2%-ի, առանց գերուսուցման նշանների։ Թեստում mAP50-ը աճել է 3,1 կետով (52,6% → 55,7%), ընդ որում բարելավվել են բոլոր հինգ դասերը։ Ճարտարապետությունը և արագությունը չեն փոխվել, այսինքն՝ արդյունքի բարելավումը ստացվել է միայն լրացուցիչ ուսուցման ժամանակի հաշվին։

Արդյունքները ցույց են տալիս **տիրույթի տեղաշարժի** ուժեղ ազդեցությունը։ Միայն VisDrone-ով ուսուցանված մոդելը, որը լավագույնն էր անօդաչու սարքի պատկերներում, ճանապարհային տեսախցիկների MIO-TCD պատկերներում ունի ընդամենը 15,1% mAP50։ MIO-TCD տվյալների ավելացումը այն բարձրացնում է մինչև 83,7%, իսկ VisDrone-ում կորուստը փոքր է (45,9% → 43,0%)։ Ավելի մեծ YOLOv8s մոդելը բարելավում է արդյունքները երկու տիրույթներում էլ (VisDrone 48,0%, MIO-TCD 86,8%), այսինքն՝ YOLOv8n-ի հզորությունը բավարար չէր երկու տիրույթները միաժամանակ լավ սովորելու համար։ Նույն մոդելի երկարացված ուսուցումը բոլոր չորս սյունակներում ավելացնում է ևս 3,3–4,6 կետ (VisDrone 51,4%, MIO-TCD 90,2%)։

Ուշագրավ է, որ MIO-TCD-ում 640 պքս մուտքը տալիս է ավելի լավ արդյունք, քան 960-ը, իսկ VisDrone-ում՝ հակառակը։ MIO-TCD-ի պատկերները փոքր են (մոտ 720×480), և դրանց մեծացումը մինչև 960 չի ավելացնում տեղեկություն, բայց փոխում է օբյեկտների մասշտաբը ուսուցման ժամանակվա համեմատ։ Ուստի ծրագրում մուտքի չափը կարգավորելի է, իսկ բարձր լուծաչափի տեսանյութերի (Full HD, 4K) համար առաջարկվում է 960 պքս։

Ամփոփ համեմատության հիման վրա որպես հիմնական առաջարկվել է **vehicle-road-yolov8s-long** մոդելը (`reports/recommended-model.json`)։ Այն ունի նույն արագությունը, ինչ vehicle-road-yolov8s-ը, քանի որ ճարտարապետությունը նույնն է։ Թույլ համակարգիչների համար vehicle-road-combined-ը (YOLOv8n) մոտ 15%-ով ավելի արագ է, իսկ անօդաչու սարքի տեսանյութերի համար՝ vehicle-hires-960-ը սալիկային ռեժիմով։

Առաջարկվող մոդելի արդյունքներն ըստ դասերի ներկայացված են աղյուսակ 2.7-ում։

Աղյուսակ 2.7 vehicle-road-yolov8s-long մոդելի արդյունքները ըստ դասերի (միավորված թեստ, 640 պքս, փակագծերում՝ vehicle-road-yolov8s)

|---|---:|---:|---:|---:|

| van | 47,8% | 41,5% | 41,9% (38,3%) | 28,6% (26,3%) |

| bus | 77,1% | 60,9% | 66,3% (64,3%) | 51,8% (49,3%) |
| motorcycle | 54,7% | 26,3% | 28,5% (24,6%) | 11,6% (9,8%) |

Լավագույն արդյունքը մարդատար ավտոմեքենաների համար է, որոնք կազմում են տվյալների մեծ մասը։ Ամենացածրը motorcycle դասն է. VisDrone-ում մոտոցիկլները շատ փոքր են (հաճախ 10 պիքսելից պակաս) և հեշտ շփոթվում են հեծանիվների հետ։ Van դասի ցածր արդյունքը բացատրվում է դրա անորոշ սահմանով car և truck դասերի հետ. նույն մեքենան տարբեր հավաքածուներում կարող է նշագրված լինել տարբեր կերպ։ Երթևեկության ընդհանուր հաշվարկի համար դասերի շփոթությունը չի փոխում մեքենաների քանակը, քանի որ NMS-ը և հաշվարկը կատարվում են առանց դասերի տարբերակման։

**Բեռնատարի և ավտոբուսի շփոթումը։** Դասերի սխալները ավելի մանրամասն ուսումնասիրելու համար յուրաքանչյուր թեստային շրջանակ համապատասխանեցվել է մոդելի ամենավստահ հայտնաբերմանը (IoU ≥ 0,5, վստահություն ≥ 0,25) առանց դասի հաշվառման, և հաշվվել է, թե որ դասն է տվել մոդելը (`scripts/evaluate_heavy.py`)։ MIO-TCD-ում (ճանապարհային տեսախցիկներ) բեռնատարների 94,2%-ը ճիշտ է դասակարգվել, և միայն 1,7%-ը՝ որպես ավտոբուս, իսկ ավտոբուսների 1,5%-ը՝ որպես բեռնատար։ VisDrone-ում (վերևից) այդ շփոթումը մոտ 10,6% է երկու ուղղությամբ։ Ամենամեծ շփոթումը van և car դասերի միջև է. MIO-TCD-ում van-երի 33%-ը, իսկ VisDrone-ում 51%-ը դասակարգվել են որպես car։ Եթե truck և bus դասերը միավորվեն մեկ «ծանր տրանսպորտ» դասի մեջ, դրա AP50-ը MIO-TCD-ում կազմում է 94,1%, VisDrone-ում՝ 55,2%։ Քանի որ HCM-ը բեռնատարներն ու ավտոբուսները դիտարկում է միասին՝ որպես ծանր տրանսպորտ, ծրագիրը հաշվետվությունում բացի հինգ դասից տալիս է նաև խմբերը (թեթև՝ car + van, ծանր՝ truck + bus, մոտոցիկլ) և ծանր տրանսպորտի բաժինը։

### Ծրագրի ճարտարապետությունը

Ծրագիրը գրված է Python 3.10–3.13 լեզվով և բաղկացած է `traffic_cnn` փաթեթից, Streamlit միջերեսից (`app.py`) և օժանդակ սկրիպտներից (`scripts/`)։ Հիմնական արտաքին գրադարաններն են Ultralytics (YOLOv8 և ByteTrack), OpenCV (տեսանյութի ընթերցում և գրառում), NumPy և Streamlit։ Ծրագիրը տեղադրվում է `pip install -e .` հրամանով և գրանցում է `traffic-cnn` հրամանը։

### Տեսանյութի մշակման հաջորդականությունը

Յուրաքանչյուր կադրի համար ծրագիրը կատարում է հետևյալ քայլերը.

1. կադրի ընթերցում ֆայլից կամ ուղիղ հոսքից և ժամանակի որոշում (ֆայլի համար՝ կադրի համարը բաժանած FPS-ի վրա, ուղիղ հոսքի համար՝ իրական ժամանակը).
2. տրանսպորտային միջոցների հայտնաբերում YOLOv8-ով (ամբողջ կադրով կամ սալիկներով) և ByteTrack-ով ID-ների վերագրում.
3. յուրաքանչյուր հետագծի հենակետի (շրջանակի ստորին եզրի միջնակետի) որոշում.
4. բոլոր հաշվման գծերի հատման ստուգում և կրկնակի ID-ների զտում.
5. տրամաչափման առկայության դեպքում՝ հենակետի փոխակերպում մետրերի, արագության թարմացում և տրամաչափված գոտում մեքենաների հաշվարկ.
6. ջերմային քարտեզի և հետագծերի թարմացում.
7. նշագրված կադրի գրառում (շրջանակներ, ID, դաս, արագություն, գծեր, գոտի, հաշվիչ) և տողերի ավելացում CSV աղյուսակներում։

Տեսանյութի ավարտից հետո հաշվարկվում են ամփոփ ցուցանիշները՝ ինտենսիվություն, արագությունների վիճակագրություն, միջին խտություն, LOS, q = k·v ստուգում, հավաստիության նախազգուշացումներ, և ամեն ինչ պահպանվում է `summary.json` ֆայլում։ Արդյունքների պանակը երբեք չի վերագրվում. յուրաքանչյուր գործարկում ստեղծում է նոր պանակ, իսկ մշակման ընթացքը պահպանվում է ատոմար կերպով, որպեսզի միջերեսը կարողանա ցույց տալ ընթացիկ վիճակը։

### Հայտնաբերում և հետագծում

Դետեկտորը կանչվում է ցածր շեմով (0,1), որպեսզի ByteTrack-ը ստանա նաև ցածր վստահությամբ շրջանակները՝ գոյություն ունեցող հետագծերի շարունակության համար, իսկ նոր հետագիծ ստեղծելու շեմը հավասար է օգտագործողի ընտրած վստահության շեմին (լռելյայն 0,3)։ NMS-ը կատարվում է առանց դասերի տարբերակման (class-agnostic, IoU 0,5). առանց դրա նույն մեքենան երբեմն հայտնաբերվում է միաժամանակ որպես car և van, ինչը հանգեցնում է երկու ID-ի և կրկնակի հաշվարկի։ Հետագծիչի պարամետրերը [5] պահպանվում են յուրաքանչյուր արդյունքի հետ (`tracker.yaml`)։

Աշխատանքի սկզբնական փուլում մշակվել է նաև **շարունակականության փորձարարական ռեժիմ** (`tracklets.py`). նոր ID-ն կապվում է վերջերս կորած հետագծի հետ, եթե կորած շրջանակի կանխատեսված դիրքը (գծային շարժման մոդելով) բավարար IoU ունի նոր շրջանակի հետ և համապատասխանեցումը միանշանակ է, իսկ մեքենայի դասը որոշվում է վստահություններով կշռված քվեարկությամբ ամբողջ հետագծի ընթացքում։ Փորձերում (3.3 բաժին) այս ռեժիմը չի բարելավել հաշվարկը, ուստի լռելյայն օգտագործվում է ստանդարտ ByteTrack-ը, իսկ փորձարարական ռեժիմը պահպանվել է որպես ընտրովի։

### Հաշվման գծի հատման կանոնը

Հաշվման գիծը տրվում է որպես A(x_A, y_A) – B(x_B, y_B) վերջավոր հատված։ Հենակետի P(x, y) նշանով հեռավորությունը AB ուղղից հաշվվում է վեկտորական արտադրյալով՝

> d(P) = [(x_B − x_A)(y − y_A) − (y_B − y_A)(x − x_A)] / |AB|  (3.1)

Նշանը ցույց է տալիս, թե գծի որ կողմում է մեքենան։ Շրջանակի տատանումների պատճառով կեղծ հատումներից խուսափելու համար օգտագործվում է **հիստերեզիս**. մեքենայի կողմը որոշվում է միայն |d| > 4 պիքսել դեպքում, իսկ գծի մոտ գտնվող կետերը կողմը չեն փոխում։ Հատումը գրանցվում է, երբ նույն ID-ի կողմը փոխվում է, ընդ որում նախորդ դիտարկումից անցել է ոչ ավելի, քան 30 կադր։ Հատման կետը որոշվում է գծային ինտերպոլյացիայով երկու դիտարկումների միջև և ստուգվում է, որ այն ընկած է AB հատվածի վրա (պրոյեկցիայի պարամետրը 0-ից 1)։ Այսպիսով, գծի կողքով անցնող մեքենաները չեն հաշվվում։ Յուրաքանչյուր ID հաշվվում է ոչ ավելի, քան մեկ անգամ, իսկ ուղղությունը որոշվում է կողմի փոփոխության նշանով։

Վերը նկարագրված ստանդարտ կանոնը բաց է թողնում երկու իրավիճակ, որոնք հայտնաբերվել են մշակման ընթացքում։

**Գծից արդեն անցած մեքենաներ։** Եթե մեքենան առաջին անգամ հայտնաբերվում է արդեն գծից անմիջապես հետո (տեսանյութի սկզբում կամ ծածկումից հետո ուշ հայտնաբերման դեպքում), այն երբեք չի փոխում կողմը և չի հաշվվում։ Նման հետագիծը հաշվվում է, եթե առաջին հայտնաբերման պահին այն գտնվում էր գծից իր շրջանակի բարձրության կեսից ոչ հեռու, իսկ հաջորդ 15 կադրերի ընթացքում հեռացել է գծից շրջանակի բարձրության առնվազն քառորդով։ Կրկնակի հաշվարկից խուսափելու համար այն չի հաշվվում, եթե նույն ուղղությամբ արդեն հաշվված մեքենա անհետացել է մոտակայքում (շրջանակի երկու բարձրությունից ոչ հեռու) վերջին 30 կադրում. դա, ամենայն հավանականությամբ, նույն մեքենան է նոր ID-ով։

**Նույն մեքենայի երկրորդ ID։** Երբեմն խոշոր մեքենան (բեռնատար) ստանում է երկու շրջանակ՝ ամբողջ մեքենայի և խցիկի, որոնք հետագծվում են առանձին ID-ներով և երկուսն էլ հատում են գիծը։ Կրկնակի ID-ների զտիչը (`DuplicateGuard`) մերժում է հատումը, եթե նույն կադրում դրա շրջանակը մեծապես համընկնում է (հատումը փոքր շրջանակի մակերեսի նկատմամբ ≥ 0,7) մեկ այլ տեսանելի ID-ի շրջանակի հետ, որը նույն ուղղությամբ գիծը հատել է վերջին 50 կադրում։ Միայն ժամանակով կամ դիրքով մոտիկությունը չի օգտագործվում, քանի որ նույն գոտում հաջորդաբար շարժվող մեքենաները հատում են գիծը մի քանի կադր տարբերությամբ գրեթե նույն կետում։

Ծրագիրը թույլ է տալիս սահմանել մի քանի հաշվման գիծ, որոնցից յուրաքանչյուրն ունի առանձին հաշվիչ և զտիչ։ Լրացուցիչ գիծը օգտագործվում է, օրինակ, տարբեր ուղղությունների կամ գոտիների առանձին հաշվարկի, ինչպես նաև արագության անկախ ստուգման համար (երկու գծերի միջև անցման ժամանակով, 3.3 բաժին)։ Բոլոր կանոնները կարելի է անջատել հրամանային տողի պարամետրերով (`--no-start-crossings`, `--no-duplicate-guard`)։

### Սալիկային հայտնաբերում

Անօդաչու սարքից արված կամ 4K կադրերում մեքենաները կարող են զբաղեցնել ընդամենը 10–20 պիքսել։ Երբ կադրը փոքրացվում է մինչև ցանցի մուտքի չափը (640 կամ 960 պիքսել), այդպիսի մեքենաները դառնում են մի քանի պիքսել և չեն հայտնաբերվում։ Սալիկային ռեժիմում (`tiling.py`), որը հիմնված է SAHI մեթոդի [18] գաղափարի վրա, կադրը բաժանվում է 20% համընկնող սալիկների (օրինակ՝ 640×640), որոնցից յուրաքանչյուրը մշակվում է ցանցով իր իսկ լուծաչափով, ինչի շնորհիվ փոքր մեքենաները մեծանում են։ Լրացուցիչ կատարվում է ամբողջ կադրի անցում՝ մեծ մեքենաների համար, որոնք չեն տեղավորվում մեկ սալիկում։

Բոլոր շրջանակները վերածվում են ամբողջ կադրի կոորդինատների և միավորվում են NMS-ով։ Առանձին կանոն հեռացնում է սալիկի ներքին եզրով կտրված շրջանակները (կես մեքենաներ), եթե դրանք օբյեկտի լավագույն տեսքը չեն. կտրված շրջանակը հեռացվում է, եթե այն մեծապես ընկած է մեկ այլ, չկտրված շրջանակի ներսում։ Միավորված հայտնաբերումները փոխանցվում են ByteTrack-ին, և հաշվարկի մնացած մասը չի փոխվում։ Սալիկային ռեժիմը մոտ 6–7 անգամ դանդաղ է (2.3 բաժին) և առաջարկվում է միայն փոքր օբյեկտներով տեսանյութերի համար։

### Տրամաչափում և արագության գնահատում

Տրամաչափումը (`calibration.py`) տրվում է JSON ֆայլով կամ միջերեսում կադրի վրա սեղմելով. չորս կետ (հեռավոր ձախ, հեռավոր աջ, մոտ աջ, մոտ ձախ), որոնք կազմում են ճանապարհի վրա ուղղանկյուն, դրա լայնությունը և երկարությունը մետրերով և երթևեկության գոտիների քանակը։ Կետերը կարող են գտնվել նաև կադրից դուրս։ Հոմոգրաֆիայի H մատրիցը հաշվվում է DLT մեթոդով (1.6 բանաձև). ծրագիրը ստուգում է, որ կետերը վերջավոր են և ոչ մի երեքը չեն գտնվում նույն ուղղի վրա։

Կադրից կադր արագության հաշվարկը անկիրառելի է. 25 կադր/վ դեպքում կադրերի միջև ժամանակը 0,04 վ է, և շրջանակի մի քանի պիքսելանոց տատանումը կտա տասնյակ կմ/ժ սխալ։ Ուստի արագությունը (`SpeedEstimator`) չափվում է **սահող պատուհանով**. յուրաքանչյուր հետագծի համար պահվում են վերջին 1 վայրկյանի դիրքերը մետրերով, և երբ պատուհանի տևողությունը հասնում է առնվազն 0,5 վայրկյանի, արագությունը հաշվվում է՝

> v = |P_world(t) − P_world(t − Δt)| / Δt · 3,6,  կմ/ժ  (3.2)

Ցուցադրվող արագությունը վերջին 15 չափումների մեդիանն է, որը կայուն է առանձին սխալների նկատմամբ։ 250 կմ/ժ-ից բարձր չափումները համարվում են ֆիզիկապես անհնար և բաց են թողնվում, սակայն դրանց քանակը պահպանվում է հավաստիության ստուգման համար։ Եթե հետագիծն ընդհատվել է պատուհանից ավելի երկար, պատուհանը վերսկսվում է, որպեսզի միջինացում չկատարվի ընդհատման վրայով։ Արագությունը չափվում է միայն տրամաչափված գոտու ներսում։

Յուրաքանչյուր հատման համար պահպանվում է մեքենայի արագությունը հատման պահին, իսկ ամփոփագրում հաշվվում են ժամանակային միջին, տարածական միջին (հարմոնիկ, 1.3 բանաձև), մեդիան և 85-րդ պերցենտիլ արագությունները՝ առանձին հաշվման գծի համար և բոլոր հետագծերի համար։ 85-րդ պերցենտիլը ճանապարհային ճարտարագիտության մեջ օգտագործվում է արագության սահմանափակումներ նշանակելու համար։

### Խտություն, սպասարկման մակարդակ և հոսքի միջակայքեր

Յուրաքանչյուր կադրում հաշվվում է տրամաչափված գոտու ներսում գտնվող մեքենաների քանակը, որից 1.2 բանաձևով ստացվում է խտությունը մեքենա/կմ և մեքենա/կմ/գոտի միավորներով։ Ամփոփագրում տրվում են միջին և առավելագույն խտությունը և միջին խտությանը համապատասխանող LOS-ը (աղյուսակ 1.1)։ Եթե հաշվման գիծը գտնվում է տրամաչափված գոտում, ծրագիրը կատարում է q = k·v_s ստուգումը. չափված ինտենսիվությունը համեմատվում է միջին խտության և տարածական միջին արագության արտադրյալի հետ, և պահպանվում է հարաբերական տարբերությունը։

Ժամանակային դինամիկան վերլուծելու համար (`flow.py`) տեսանյութը բաժանվում է հավասար միջակայքերի (5, 10, 30 կամ 60 վայրկյան), և յուրաքանչյուր միջակայքի համար հաշվվում են հատումների քանակը ըստ ուղղությունների, ինտենսիվությունը, տեսանելի մեքենաների միջին և առավելագույն քանակը, միջին արագությունները և խտությունը (`flow_windows.csv`)։

### Ֆիզիկական հավաստիության ստուգում և արագացված տեսանյութեր

Ինտերնետում հասանելի շատ «երթևեկության» տեսանյութեր արագացված են (time-lapse) կամ մոնտաժված։ Նման տեսանյութում ծրագիրը ճիշտ կհաշվի մեքենաները, սակայն կստանա ֆիզիկապես անհնար արագություններ և ինտենսիվություն։ Ուստի ամփոփագրում ավտոմատ ստուգվում են հետևյալ պայմանները (`plausibility_issues`).

- մեդիան արագությունը 160 կմ/ժ-ից բարձր է.
- 250 կմ/ժ-ից բարձր չափումները կազմում են 30%-ից ավելին (առնվազն 10 չափման դեպքում).
- ինտենսիվությունը մեկ գոտու համար գերազանցում է 2400 մեքենա/ժամ թողունակությունը.
- չափված q-ն և k·v_s արտադրյալը տարբերվում են ավելի քան երկու անգամ։

Որևէ պայմանի խախտման դեպքում միջերեսը ցույց է տալիս նախազգուշացում։ Լրացուցիչ, առանց տրամաչափման, չափվում է մեքենաների տեսանելի տեղաշարժը մեկ կադրում՝ արտահայտված սեփական շրջանակի բարձրությամբ (`motion.py`)։ Արագացված տեսանյութում մեքենաները մեկ կադրում «ցատկում» են իրենց չափի ավելի մեծ մասով։ Այս ցուցանիշը կախված է նաև տեսախցիկի անկյունից, ուստի այն չի օգտագործվում ավտոմատ որոշման համար, այլ օգնում է ընտրել ժամանակային մասշտաբը։ Եթե արագացման գործակիցը հայտնի է, այն տրվում է `--time-scale` պարամետրով (օրինակ՝ 4 քառապատիկ արագացման դեպքում), և բոլոր ժամանակները, արագությունները ու ինտենսիվությունները հաշվվում են իրական ժամանակով։

### Ուղիղ հոսքի մշակում

Բացի ֆայլերից, ծրագիրն ընդունում է ուղիղ հոսքեր (`sources.py`). համակարգչի տեսախցիկ (0, 1, …), IP տեսախցիկ (`rtsp://`), HLS/MJPEG հասցե և YouTube-ի ուղիղ հեռարձակում (yt-dlp գրադարանի միջոցով)։ Ուղիղ հոսքի դեպքում կադրերը կարդացվում են առանձին հոսքում (thread), և պահվում է միայն ամենավերջին կադրը. եթե մշակումն ավելի դանդաղ է, քան հոսքը, հին կադրերը բաց են թողնվում, և ուշացում չի կուտակվում։ Յուրաքանչյուր կադրի ժամանակը վերցվում է իրական ժամացույցից, ուստի արագությունները ճիշտ են նույնիսկ անհավասարաչափ կադրահաճախության դեպքում։ Մշակումը դադարեցվում է օգտագործողի կողմից կամ `--max-seconds` պարամետրով։ Երկար աշխատանքի ժամանակ հիշողությունը սահմանափակ է. հին հետագծերի վիճակները պարբերաբար ջնջվում են։

## 3.2. ՕԳՏԱԳՈՐԾՈՂԻ ՄԻՋԵՐԵՍԸ ԵՎ ԾՐԱԳՐԻ ՍՏՈՒԳՈՒՄԸ

### Օգտագործողի միջերես և արտահանում

Միջերեսը (`app.py`) իրականացված է Streamlit գրադարանով, ամբողջությամբ հայերեն լեզվով, և բացվում է դիտարկիչում (http://127.0.0.1:8501)։ Այն ունի չորս ներդիր՝ «Տեսանյութի վերլուծություն», «Հաշվարկի ստուգում», «Ուսուցում և արդյունքներ» և «Տվյալներ»։ Վերլուծության ներդիրում օգտագործողը ընտրում է տեսանյութի աղբյուրը (ցուցադրական, սեփական ֆայլ կամ ուղիղ հոսք), մոդելը և մուտքի չափը, կադրի վրա սեղմելով տեղադրում է հաշվման գծերը և տրամաչափման կետերը (նկ. 3.2), ընտրում է վստահության շեմը, սարքը (CPU, MPS, CUDA) և վերլուծության միջակայքը։

![Նկ. 3.2. Հաշվման գծի և տրամաչափման կետերի տեղադրումը միջերեսում](reports/thesis/ui/e2e-points.png)

Մշակման ընթացքում ցուցադրվում են ընթացիկ կադրը, առաջընթացը և հատումների քանակը (նկ. 3.3)։ Ավարտից հետո ցուցադրվում են նշագրված տեսանյութը, հիմնական ցուցանիշները, ժամանակային դինամիկայի և արագությունների բաշխման գրաֆիկները, ջերմային քարտեզը, հետագծերը, հավաստիության նախազգուշացումները, և հնարավոր է ներբեռնել բոլոր ֆայլերը։

![Նկ. 3.3. Տեսանյութի մշակումը միջերեսում](reports/thesis/ui/e2e-results.png)

«Հաշվարկի ստուգում» ներդիրում օգտագործողը կարող է կադր առ կադր նշագրել իրական հատումները (առանց CNN-ի կանխատեսումների, որպեսզի նշագրումը անկախ լինի) և համեմատել դրանք ծրագրի արդյունքի հետ (2.2 բաժին)։ «Ուսուցում և արդյունքներ» ներդիրը ցույց է տալիս ավարտված փորձերի աղյուսակը, մուտքի չափի ազդեցությունը և UA-DETRAC ստուգման արդյունքները։

### Համակարգային պահանջներ և տեղադրում

Ծրագիրն աշխատում է macOS, Linux և Windows օպերացիոն համակարգերում՝ Python 3.10–3.13 տարբերակներով։ Առաջարկվում է առնվազն 8 ԳԲ օպերատիվ հիշողություն։ Գրաֆիկական արագացուցիչը պարտադիր չէ. Apple Silicon համակարգիչներում օգտագործվում է MPS սարքը, NVIDIA քարտերով համակարգիչներում՝ CUDA, իսկ մնացած դեպքերում՝ CPU (ավելի դանդաղ)։

Տեղադրման համար պետք է կատարել հետևյալ հրամանները.

```
git clone https://github.com/marrr862/traffic-cnn.git
cd traffic-cnn
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python scripts/download_assets.py
```

Վերջին հրամանը ներբեռնում է չորս ուսուցանված մոդելները (vehicle-road-yolov8s-long, vehicle-road-yolov8s, vehicle-road-combined, vehicle-hires-960) և երկու ցուցադրական տեսանյութերը՝ ստուգելով դրանց SHA-256 հեշերը։ Ուղիղ հոսքով YouTube-ից աշխատելու համար անհրաժեշտ է լրացուցիչ տեղադրել `pip install -e '.[live]'`։

### Միջերեսի գործարկում և տեսանյութի վերլուծություն

Միջերեսը գործարկվում է հրամանով.

```
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

macOS-ում կարելի է պարզապես գործարկել `run_app.command` ֆայլը։ Դիտարկիչում բացվում է http://127.0.0.1:8501 հասցեն։ Տեսանյութի վերլուծության համար.

1. «Տեսանյութի վերլուծություն» ներդիրում ընտրել աղբյուրը՝ ցուցադրական տեսանյութ, սեփական ֆայլ (MP4, AVI, MOV, MKV) կամ ուղիղ հոսք (տեսախցիկի համար կամ URL).
2. ընտրել մոդելը (լռելյայն՝ առաջարկվողը) և մուտքի չափը.
3. «Հաշվման գծեր» բաժնում կադրի վրա երկու սեղմումով տեղադրել հիմնական գծի A և B կետերը, անհրաժեշտության դեպքում՝ լրացուցիչ գծեր.
4. «Տրամաչափում» բաժնում ընտրել տրամաչափման եղանակը. առանց տրամաչափման (միայն հաշվարկ), պատրաստի JSON ֆայլ կամ ձեռքով չորս կետ։ Ձեռքով եղանակի դեպքում կադրի վրա նշվում են ճանապարհի ուղղանկյան չորս անկյունները (հեռավոր ձախ, հեռավոր աջ, մոտ աջ, մոտ ձախ) և մուտքագրվում են դրա լայնությունը, երկարությունը մետրերով և գոտիների քանակը։ Չափերը կարելի է որոշել գծանշումից (օրինակ, ընդհատվող գծի պարբերությունը) կամ քարտեզից.
5. ընտրել վստահության շեմը (լռելյայն 0,3), սարքը, հետագծման ռեժիմը և վերլուծության միջակայքը.
6. սեղմել «Մշակել տեսանյութը» կոճակը։

Մշակման ընթացքում ցուցադրվում է ընթացիկ կադրը և առաջընթացը, իսկ ուղիղ հոսքի դեպքում մշակումը կարելի է կանգնեցնել ցանկացած պահի՝ արդյունքները պահպանելով։

### Արդյունքների մեկնաբանումը

Ավարտից հետո ցուցադրվում են.

- հատումների ընդհանուր քանակը, ըստ ուղղությունների և դասերի, ինտենսիվությունը մեքենա/ժամ.
- տրամաչափման առկայության դեպքում՝ միջին, մեդիան և 85-րդ պերցենտիլ արագությունները, միջին խտությունը, սպասարկման մակարդակը և q = k·v ստուգման արդյունքը.
- գրաֆիկներ ժամանակի ընթացքում՝ տեսանելի մեքենաներ, կուտակային հաշվարկ, ինտենսիվություն և արագություն ըստ միջակայքերի, արագությունների բաշխում.
- ջերմային քարտեզը և հետագծերը.
- նշագրված տեսանյութը և բոլոր ֆայլերի ներբեռնման կոճակները։

Ուղղությունների անվանումները կախված են գծի կետերի հերթականությունից։ Հորիզոնական գծի համար, որը տեղադրված է ձախից աջ, «դեպի կադրի ստորին եզր» նշանակում է դեպի տեսախցիկ շարժվող մեքենաներ, եթե տեսախցիկը ուղղված է ճանապարհի երկայնքով։

Եթե ծրագիրը ցույց է տալիս հավաստիության նախազգուշացում (օրինակ, մեդիան արագությունը գերազանցում է 160 կմ/ժ կամ ինտենսիվությունը գերազանցում է գոտու թողունակությունը), պետք է ստուգել տրամաչափման չափերը, գոտիների քանակը և արդյոք տեսանյութը արագացված չէ։ Արագացված տեսանյութի համար հրամանային տողում տրվում է `--time-scale` գործակիցը։

Կարճ տեսանյութի ինտենսիվությունը (մեքենա/ժամ) հաշվարկային մեծություն է և չի նշանակում, որ ամբողջ ժամվա ընթացքում հոսքը նույնն է։ Արժանահավատ ժամային ինտենսիվության համար անհրաժեշտ է առնվազն 15 րոպե դիտարկում։

### Հաշվարկի ստուգումը սեփական տեսանյութում

Սեփական տեսանյութում ծրագրի ճշտությունը ստուգելու համար «Հաշվարկի ստուգում» ներդիրում ընտրվում է ավարտված արդյունքը և «Նշագրում հավելվածում» ռեժիմը։ Ցուցադրվում են սկզբնական կադրերը առանց CNN-ի նշագրման, որպեսզի օգտագործողի նշագրումը անկախ լինի ծրագրի կանխատեսումներից։ Կադրերով շարժվելով՝ յուրաքանչյուր իրական մեքենայի համար նշվում են հատման կադրերի միջակայքը, դասը և ուղղությունը։ Նշագրումը պահպանվում է `manual-reference.json` ֆայլում։ Համեմատման արդյունքում ցուցադրվում են համընկած, բաց թողնված և ավելորդ իրադարձությունները, դասի սխալները և precision, recall, F1 ցուցանիշները։

### Ծրագրի ավտոմատ ստուգումներ

Ծրագրի ճշտությունը ստուգվում է 76 ավտոմատ թեստով (`tests/` պանակ, `python -m unittest discover -s tests`)։ Դրանք ընդգրկում են.

- երկրաչափությունը՝ գծի հատում, վերջավոր հատված, հիստերեզիս, ուղղություններ, թեք գծեր.
- հաշվման հատուկ դեպքերը՝ ID-ի փոխարկում, հարևան մեքենաներ նույն գոտում, գծից արդեն անցած մեքենաներ, կրկնակի ID-ներ.
- տրամաչափումը՝ հայտնի հոմոգրաֆիայի վերականգնում, այլասերված կետերի մերժում, արագություն սինթետիկ հետագծով.
- հոսքի վիճակագրությունը, LOS-ը, q = k·v ստուգումը և հավաստիության կանոնները.
- սալիկային հայտնաբերման պատուհանները և միավորումը.
- տվյալների փոխակերպումը, կրկնօրինակների հայտնաբերումը, իրադարձությունների համեմատումը.
- ուղիղ հոսքի աղբյուրները, միջերեսի բացումը և տեսանյութի ամբողջական մշակումը (եթե տեղական կշիռները առկա են)։

Թեստերը ստուգում են ծրագրի տրամաբանությունը, բայց ոչ CNN-ի ճշտությունը, որը գնահատվում է առանձին փորձերով (2-րդ և 3-րդ գլուխներ)։ Վերջին գործարկման ժամանակ բոլոր 76 թեստերն անցել են մոտ 25 վայրկյանում։

Առաջին, **ընդհանուր քանակը թաքցնում է սխալները**։ Սկզբնական մոդելների մեծ մասը հաշվել է ճիշտ 10 մեքենա, սակայն միայն 9-ն էին իրական. մեկ մեքենա բաց է թողնվել, իսկ մեկ այլ մեքենա կրկնակի հաշվվել է ID-ի փոխարկման պատճառով։ Զրոյից ուսուցանված մոդելի 11 հատումներից մեկը կեղծ էր։

Երկրորդ, **շարունակականության փորձարարական ռեժիմը չի բարելավել հաշվարկը** (8 համընկած 9-ի փոխարեն), ուստի այն չի ընտրվել լռելյայն։

Երրորդ, **առանց դասերի տարբերակման NMS-ը (class-agnostic) վերացրել է ավելորդ իրադարձությունները**. նախկինում նույն մեքենան երբեմն միաժամանակ հայտնաբերվում էր որպես երկու դաս և ստանում էր երկու ID։ Բոլոր հաջորդ տարբերակներում ավելորդ հատումներ չկան։ Կրկնակի ID-ների զտիչը (3.1 բաժին) լրացուցիչ պաշտպանություն է նույն մեքենայի երկու շրջանակի դեպքի համար։

Չորրորդ, **ճանապարհային տվյալները բարելավել են դասակարգումը**։ VisDrone-ով ուսուցանված մոդելները բեռնատարը դասակարգել են որպես bus կամ van (վերևից դիտման դեպքում բեռնատարի և ավտոբուսի տեսքը նման է), իսկ MIO-TCD-ով ուսուցանված vehicle-road-combined և vehicle-road-yolov8s մոդելները՝ ճիշտ՝ truck։ Սակայն երկարացված ուսուցմամբ մոդելը երկու բեռնատարները կրկին դասակարգել է որպես bus. երկրորդ բեռնատարը կադրերի 86%-ում նշվել է որպես bus, ուստի հետագծի պատմությամբ քվեարկությունը դա չէր ուղղի։ Թեստային ընտրանքներում truck/bus շփոթումը փոքր է (MIO-TCD-ում մոտ 2%, 2.3 բաժին), այսինքն՝ սա ընդհանուր խնդիր չէ, այլ տիրույթի տարբերություն. տեսանյութում եվրոպական արկղային բեռնատարներ են, որոնք դիմացից նման են ավտոբուսի, իսկ MIO-TCD-ում հիմնականում հյուսիսամերիկյան տրանսպորտ է։ Խմբերով հաշվարկը ճիշտ է՝ 8 թեթև և 2 ծանր, ինչպես էտալոնում։

Հինգերորդ, մնացած բաց թողնված իրադարձությունը առաջին բեռնատարն էր, որը տեսանյութի առաջին կադրում արդեն գտնվում է գծից անմիջապես հետո և երբեք չի փոխում կողմը։ Այս դեպքի համար մշակվել է գծից արդեն անցած մեքենաների կանոնը (3.1 բաժին), որից հետո vehicle-road-yolov8s մոդելը ճիշտ է հաշվել բոլոր 10 մեքենաները՝ ճիշտ ուղղություններով (7 և 3) և ճիշտ դասերով (8 car, 2 truck)։ Event F1-ը 94,7%-ից աճել է մինչև 100%։ Առաջարկվող vehicle-road-yolov8s-long մոդելը նույնպես հաշվել է բոլոր 10 մեքենաները ճիշտ ուղղություններով (F1 100%) և ճիշտ խմբերով (8 թեթև, 2 ծանր), բայց բեռնատարները նշել է որպես bus։

Պետք է ընդգծել, որ այս տեսանյութն օգտագործվել է կանոնների մշակման համար, իսկ էտալոնը նախնական է, ուստի վերջնական 10/10 արդյունքը **մշակման արդյունք է, ոչ թե ճշտության անկախ գնահատական**։ Անկախ ստուգումը ներկայացված է հաջորդ բաժնում։

### Արագացված տեսանյութի հայտնաբերումը

Տեսանյութ 2-ը (քաղաքային արագընթաց ճանապարհ, 42,5 վ) մշակվել է նույն մոդելով և հեղինակի տրամաչափմամբ (3 գոտի, 120 մ)։ Ծրագիրը գրանցել է 449 հատում, ինչը համապատասխանում է 37 995 մեքենա/ժամ ինտենսիվությանը, այսինքն՝ մոտ 12 700 մեքենա/ժամ մեկ գոտու համար։ Դա ավելի քան հինգ անգամ գերազանցում է երթևեկության գոտու ֆիզիկական թողունակությունը (մոտ 2400)։

Ծրագիրն ավտոմատ կերպով հայտնաբերել է հավաստիության խախտումները (աղյուսակ 3.7) և ցույց տվել է նախազգուշացում՝ տեսանյութը, ամենայն հավանականությամբ, արագացված է։

Երկու YOLOv8s մոդելների արագությունը նույնն է (տարբերությունները համակարգչի բեռնվածությունից են)։ Զուտ հայտնաբերման ժամանակը vehicle-road-yolov8s մոդելի համար 960 պքս մուտքով կազմում է մոտ 26 մվ մեկ պատկերի համար (մոտ 38 պատկեր/վ), այսինքն՝ ժամանակի զգալի մասը ծախսվում է 4K կադրերի ապակոդավորման, մասշտաբավորման և նշագրված տեսանյութի կոդավորման վրա։ Ուղիղ հոսքի համար, որտեղ նշագրված տեսանյութի գրառումը կարող է ավելի փոքր լուծաչափով լինել, մոդելը թույլ է տալիս մշակել 10 կադր/վ և ավելի, ինչը բավարար է հաշվարկի համար, քանի որ 120 կմ/ժ արագությամբ մեքենան 0,1 վայրկյանում անցնում է ընդամենը 3,3 մետր։ Չափումները կատարվել են սովորական աշխատանքային բեռնվածության պայմաններում և ունեն մոտավոր բնույթ։

### Արդյունքների կիրառելիության սահմանները

Ստացված արդյունքները պետք է մեկնաբանել հետևյալ սահմանափակումներով.

- տեսանյութ 1-ի էտալոնը նախնական է և պատրաստված է առանց անկախ ստուգման, իսկ տեսանյութն օգտագործվել է կանոնների մշակման համար.
- արտաքին ստուգումը կատարվել է միայն մեկ 12 վայրկյանանոց հաջորդականությամբ (5 իրադարձություն).
- արագության բացարձակ ճշտությունը չի ստուգվել անկախ չափիչ սարքով, իսկ տրամաչափումները մոտավոր են.
- բոլոր տեսանյութերը ցերեկային են և լավ եղանակով. գիշերը, անձրևի, ձյան և մառախուղի պայմաններում ճշտությունը չի գնահատվել.
- յուրաքանչյուր մոդել ուսուցանվել է մեկ անգամ (մեկ seed), ուստի փոքր տարբերությունների նշանակալիությունը հայտնի չէ.
- MIO-TCD-ում նույն տեսախցիկի կադրերը կարող են լինել train և test ընտրանքներում, ինչը կարող է լավատեսական դարձնել MIO-TCD-ի թեստային արդյունքները.
- խտությունը և LOS-ը հաշվվում են ֆիզիկական մեքենաներով, առանց ծանր տրանսպորտի համարժեքի.
- մեթոդը ենթադրում է հարթ ճանապարհ և անշարժ տեսախցիկ։

# ԳԼՈՒԽ 4. ՏՆՏԵՍԱԳԻՏՈՒԹՅՈՒՆ

## 4.1. ԵՐԹԵՎԵԿՈՒԹՅԱՆ ՀՈՍՔԻ ՎԵՐԼՈՒԾՈՒԹՅԱՆ ԾՐԱԳՐԱՅԻՆ ՄԻՋՈՑԻ ՄՇԱԿՄԱՆ ԻՆՔՆԱՐԺԵՔԸ

Ժամանակակից տնտեսական պայմաններում ցանկացած ծրագրային արտադրանքի մշակում պահանջում է տնտեսական հիմնավորում։ Նոր տեխնիկայի և տեխնոլոգիական գործընթացների տեխնիկատնտեսական գնահատման կարևորագույն ցուցանիշներից է ինքնարժեքը։

Արտադրանքի կամ ծառայության ինքնարժեքը արտադրանքի (ծառայության) մշակման և իրացման վրա կատարված բոլոր ծախսերի գումարն է՝ արտահայտված դրամով։ Ինքնարժեքի մեջ արտահայտվում են սպառված նյութական միջոցները, սարքավորումների մաշվածքը և աշխատողների աշխատավարձը։

Ինքնարժեքի մեջ մտնող ծախսերը դասակարգվում են ըստ տնտեսական տարրերի և ըստ կալկուլյացիոն հոդվածների։ Աշխատանքում կիրառված է ծախսերի հետևյալ դասակարգումն ըստ կալկուլյացիոն հոդվածների՝

1. համալրող առարկաներ,
2. էլեկտրաէներգիայի ծախսեր,
3. աշխատողների հիմնական աշխատավարձ,
4. աշխատողների լրացուցիչ աշխատավարձ,
5. սարքավորումների շահագործման և պահպանման ծախսեր,
6. տարածքի վարձակալության ծախս,
7. ընդհանուր տնտեսական ծախսեր։

**Լրիվ ինքնարժեք (1–7 կետերի գումարը)։**

Հաշվարկի օբյեկտը երթևեկության հոսքի վերլուծության ծրագրային միջոցն է, որը ներառում է ուսուցանված CNN մոդելները, տեսանյութի մշակման ծրագիրը, օգտագործողի միջերեսը և ավտոմատ թեստերը։ Մշակման տևողությունն ընդունված է 6 ամիս։ Ծրագրի ստեղծման համար օգտագործված բոլոր ծրագրային գործիքները (Python, PyTorch, Ultralytics, OpenCV, Streamlit) և տվյալների հավաքածուները բաց են և անվճար, ուստի ծրագրային ապահովման լիցենզիաների ծախս չկա։

Հաշվարկի համար ելքային տվյալներ են հանդիսանում՝

- մշակման համար անհրաժեշտ համալրող առարկաների քանակը և անվանացանկը,
- աշխատանքի փուլերի ժամանակային նորմերը և ժամային դրույքաչափերը,
- պարգևատրման չափը (26%),
- լրացուցիչ աշխատավարձի չափը (15%),
- սարքավորումների պահպանման և ընթացիկ վերանորոգման դրույքաչափերը (2,1% և 4,5%),
- ընդհանուր տնտեսական ծախսերի դրույքաչափը (129%)։

### 1. Համալրող առարկաների ծախսի հաշվարկ

Գնված բաղադրիչների արժեքը որոշվում է հետևյալ բանաձևով՝

> Ծհ.առ = Σ Քi · Գi

որտեղ Քi-ն i-րդ տեսակի գնված բաղադրիչների քանակն է, հատ, Գi-ն՝ i-րդ բաղադրիչի միավորի գինը։ Հաշվարկի արդյունքները բերված են աղյուսակ 4.1-ում։

Աղյուսակ 4.1 Համալրող առարկաների ծախսի հաշվարկի արդյունքները

| Բաղադրիչի անվանումը և տեսակը | Քանակը, հատ | Միավորի գինը, դրամ | Արժեքը, դրամ |
|---|---:|---:|---:|
| Արտաքին SSD կրիչ 1 ՏԲ (տվյալների հավաքածուների և մոդելների պահպանման համար) | 1 | 45 000 | 45 000 |
| Գրասենյակային պարագաներ (թուղթ, տպագրություն, կազմում) | 1 | 25 000 | 25 000 |
| **Ընդամենը** | | | **70 000** |

Ընդամենը՝ 70 000 դրամ։

### 2. Էլեկտրաէներգիայի ծախսի հաշվարկ

Համակարգչի և մոնիտորի աշխատանքի համար էլեկտրաէներգիայի ծախսը մշակման ամբողջ ժամանակահատվածի համար որոշվում է հետևյալ բանաձևով՝

> Է = Վ · Աէ

որտեղ Վ-ն էլեկտրաէներգիայի ծախսն է, կՎտ·ժ, Աէ-ն՝ 1 կՎտ·ժ էլեկտրաէներգիայի արժեքը (50 դրամ)։

> Վ = Հ · Ֆh · Գբ · Կմ / (Ղ1 · Ղ2)

որտեղ Հ-ն սարքավորումների ընդհանուր հզորությունն է (համակարգիչ և մոնիտոր՝ 0,1 կՎտ), Ֆh-ն՝ աշխատաժամանակի իրական ֆոնդը (6 ամիս × 22 օր × 8 ժամ = 1056 ժամ), Գբ-ն՝ բեռնվածության միջին գործակիցը (0,9), Կմ-ն՝ ցանցում կորուստների գործակիցը (0,8), Ղ1-ը և Ղ2-ը՝ օգտակար գործողության գործակիցները (0,95 և 0,9)։

Մեր օրինակի համար՝

> Վ = 0,1 · 1056 · 0,9 · 0,8 / (0,95 · 0,9) ≈ 88,9 կՎտ·ժ

> Է = 88,9 · 50 ≈ 4446 դրամ

Ժամանակի մեծ մասը կազմում է ծրագրավորումը և փաստաթղթավորումը, իսկ CNN մոդելների ուսուցումը կատարվել է նոութբուքի ներկառուցված գրաֆիկական պրոցեսորով, որի էներգածախսը փոքր է, ուստի էլեկտրաէներգիայի ծախսը համեմատաբար աննշան է։

### 3. Աշխատողների հիմնական աշխատավարձի հաշվարկը

Աշխատողների հիմնական աշխատավարձի մեջ մտնում են՝

- գործարքային դրույքաչափերով աշխատավարձ,
- ժամավճարային աշխատավարձ,
- պարգևավճար։

Աշխատավարձն ըստ աշխատանքի փուլերի որոշվում է հետևյալ բանաձևով՝

> Ահիմ = Ժդ · Աարտ

որտեղ Ժդ-ն ժամային դրույքաչափն է, Աարտ-ը՝ ամսական ժամային նորմը։ Հաշվարկման արդյունքները բերված են աղյուսակ 4.2-ում։

Աղյուսակ 4.2 Աշխատողների հիմնական աշխատավարձի հաշվարկի արդյունքները (ամսական)

| Աշխատանքի փուլը | Վճարման ձևը | Ժամանակային նորմ, ժամ | Ժամային դրույք, դրամ | Տարիֆային ֆոնդ, դրամ |
|---|---|---:|---:|---:|
| Խնդրի վերլուծություն և նախագծում | Ժամավճարային | 30 | 3500 | 105 000 |
| Տվյալների պատրաստում և CNN-ի ուսուցում | Ժամավճարային | 32 | 5000 | 160 000 |
| Ծրագրավորում | Ժամավճարային | 40 | 5000 | 200 000 |
| Թեստավորում և փաստաթղթավորում | Ժամավճարային | 30 | 4500 | 135 000 |
| **Ընդամենը** | | | | **600 000** |

Պարգևատրման չափը որոշվում է հետևյալ բանաձևով՝

> Պ = Ահիմ · Պդ / 100

որտեղ Պդ-ն պարգևատրման դրույքաչափն է, %։

> Պ = 600 000 · 26 / 100 = 156 000 դրամ

Ընդամենը հիմնական աշխատավարձը կկազմի՝

> 600 000 + 156 000 = 756 000 դրամ/ամսական կամ 756 000 · 6 = 4 536 000 դրամ՝ մշակման ամբողջ ժամանակահատվածի համար։

### 4. Աշխատողների լրացուցիչ աշխատավարձի հաշվարկը

Լրացուցիչ աշխատավարձի մեջ մտնում են հերթական և լրացուցիչ արձակուրդների, արձակուրդային վճարների և այլ երաշխավորված վճարումների ծախսերը։ Այն հաշվարկվում է հետևյալ բանաձևով՝

> Ալր = Ահիմ · Ալր.դ / 100

### 9. Շահույթի և միավորի գնի հաշվարկը

Ծրագրային միջոցի գինն իր մեջ ընդգրկում է ինքնարժեքը և շահույթը։ Շահույթի հաշվարկն իրականացվում է հետևյալ բանաձևով՝

> Շ = Ի · Շդ / 100

որտեղ Ի-ն ինքնարժեքն է, Շդ-ն՝ շահույթի դրույքաչափը (18%)։ Մեր օրինակի համար՝

> Շ = 11 669 262 · 18 / 100 ≈ 2 100 467 դրամ

Գնի հաշվարկն իրականացվում է հետևյալ կերպ՝

> Գ = Ի + Շ = 11 669 262 + 2 100 467 = 13 769 729 դրամ

Ծրագրային միջոցի բացթողման գինը որոշվում է հետևյալ բանաձևով՝

> Գբաց = Գ + ԱԱՀ

որտեղ ԱԱՀ-ն ավելացված արժեքի հարկն է (20%)։

> Գբաց = 13 769 729 + 13 769 729 · 20 / 100 ≈ 16 523 675 դրամ

Այսպիսով, կատարված հաշվարկների արդյունքում ստացվել է, որ երթևեկության հոսքի վերլուծության ծրագրային միջոցի ինքնարժեքը կկազմի 11 669 262 դրամ, իսկ բացթողման գինը՝ 16 523 675 դրամ։ Ինքնարժեքի հիմնական մասը կազմում են աշխատավարձը և ընդհանուր տնտեսական ծախսերը, քանի որ ծրագիրը մշակվել է բաց կոդով գործիքներով և սովորական համակարգչի վրա՝ առանց մասնագիտացված սերվերների և թանկարժեք լիցենզիաների։

Ծրագրային միջոցի տնտեսական առավելությունն այն է, որ այն օգտագործում է արդեն տեղադրված տեսախցիկները և չի պահանջում ճանապարհային աշխատանքներ, ինչպես ինդուկտիվ օղակային տվիչների տեղադրման դեպքում։ Մեկ անգամ մշակված ծրագիրը կարող է կիրառվել անսահմանափակ թվով տեսախցիկների համար, ուստի մեկ դիտակետի հաշվով ծախսը նվազում է կիրառման ծավալի աճին զուգընթաց։


# ԳԼՈՒԽ 5. ԲՆԱՊԱՀՊԱՆՈՒԹՅՈՒՆ

## 5.1. ԱՎՏՈՏՐԱՆՍՊՈՐՏԻ ԱԶԴԵՑՈՒԹՅՈՒՆԸ ՇՐՋԱԿԱ ՄԻՋԱՎԱՅՐԻ ՎՐԱ ԵՎ ԵՐԹԵՎԵԿՈՒԹՅԱՆ ՄՈՆԻԹՈՐԻՆԳԻ ԴԵՐԸ

Ավտոմոբիլային տրանսպորտը քաղաքներում մթնոլորտային օդի աղտոտման հիմնական աղբյուրներից է։ Ներքին այրման շարժիչների արտանետվող գազերը պարունակում են ածխածնի օքսիդ (CO), ազոտի օքսիդներ (NOx), չայրված ածխաջրածիններ (CH), կախված մասնիկներ (PM10, PM2,5), ծծմբի միացություններ, ինչպես նաև ածխածնի երկօքսիդ (CO₂), որը հիմնական ջերմոցային գազն է։ Բացի արտանետվող գազերից, կախված մասնիկներ են առաջանում նաև անվադողերի և արգելակների մաշվածքից և ճանապարհի ծածկույթի քայքայումից։ Ավտոտրանսպորտը նաև քաղաքային աղմուկի հիմնական աղբյուրն է։

**Աղտոտիչների հիմնական ազդեցությունները մարդու առողջության և շրջակա միջավայրի վրա՝**

- ածխածնի օքսիդը (CO) կապվում է արյան հեմոգլոբինի հետ և նվազեցնում թթվածնի փոխադրումը օրգանիզմի հյուսվածքներին,
- ազոտի օքսիդները (NOx) գրգռում են շնչառական ուղիները և մասնակցում ֆոտոքիմիական սմոգի ու թթվային անձրևների առաջացմանը,
- կախված մասնիկները (PM2,5) թափանցում են թոքերի խորը հատվածներ և արյան մեջ, բարձրացնում սրտանոթային և շնչառական հիվանդությունների ռիսկը,
- ածխաջրածինների որոշ բաղադրիչներ (օրինակ՝ բենզոլը) քաղցկեղածին են,
- ածխածնի երկօքսիդը (CO₂) նպաստում է կլիմայի գլոբալ փոփոխությանը,
- տրանսպորտային աղմուկը առաջացնում է քնի խանգարումներ, սթրես և աշխատունակության անկում։

Արտանետումների ծավալը կախված է ոչ միայն մեքենաների քանակից, այլև երթևեկության ռեժիմից։ Խցանումների ժամանակ մեքենաները շարժվում են ցածր արագությամբ, հաճախակի կանգառներով և արագացումներով, ինչի հետևանքով մեկ կիլոմետրի վրա վառելիքի ծախսը և արտանետումները զգալիորեն աճում են։ Ծանր բեռնատարները և ավտոբուսները, որոնք սովորաբար կազմում են հոսքի փոքր մասը, արտանետում են մեկ կիլոմետրի վրա մի քանի անգամ ավելի շատ նյութեր, քան մարդատար ավտոմեքենաները։ Ուստի երթևեկության կառավարման բարելավումը (լուսացույցային ցիկլերի օպտիմալացում, խցանումների կանխարգելում, ծանր տրանսպորտի երթուղիների պլանավորում) անմիջականորեն նվազեցնում է շրջակա միջավայրի բեռնվածությունը։

Հայաստանի Հանրապետությունում մթնոլորտային օդի պահպանության հարաբերությունները կարգավորվում են «Մթնոլորտային օդի պահպանության մասին» ՀՀ օրենքով [25], որը սահմանում է աղտոտող նյութերի արտանետումների նորմավորման և վերահսկման սկզբունքները։ Արտանետումների գնահատման և մոնիթորինգի համար անհրաժեշտ են տվյալներ երթևեկության ինտենսիվության և կազմի մասին։

**Ծրագրային միջոցի կիրառումը արտանետումների գնահատման համար։** Մշակված ծրագիրը որոշում է ինտենսիվությունը ըստ տրանսպորտային միջոցների դասերի, արագությունները և խտությունը, որոնք արտանետումների հաշվարկային մոդելների (օրինակ՝ EMEP/EEA ուղեցույցի COPERT մեթոդիկա [26]) մուտքային տվյալներն են։ Ճանապարհի L երկարությամբ հատվածում մեկ ժամում արտանետվող նյութի զանգվածը մոտավորապես որոշվում է հետևյալ բանաձևով՝

> E = Σ qc · L · ec  (5.1)

որտեղ qc-ն c դասի մեքենաների ինտենսիվությունն է, մեքենա/ժամ, L-ը՝ հատվածի երկարությունը, կմ, ec-ն՝ c դասի մեքենայի միջին արտանետման գործակիցը, գ/կմ։

Որպես օրինակ գնահատվել են CO₂-ի արտանետումները տեսանյութ 1-ի մայրուղու հատվածում (գլուխ 3)։ Ծրագիրը որոշել է 1673 մեքենա/ժամ ինտենսիվություն, որից 80%-ը մարդատար ավտոմեքենաներ են, 20%-ը՝ բեռնատարներ, իսկ տրամաչափված հատվածի երկարությունը 250 մ է։ Արտանետման գործակիցները ընդունվել են մոտավոր միջին արժեքներով. մարդատար ավտոմեքենայի համար՝ 170 գ/կմ, ծանր բեռնատարի համար՝ 800 գ/կմ։ Հաշվարկի արդյունքները բերված են աղյուսակ 5.1-ում։

Աղյուսակ 5.1 CO₂-ի արտանետումների գնահատումը տեսանյութ 1-ի հատվածում (L = 0,25 կմ)

| Դաս | Ինտենսիվություն, մեքենա/ժամ | Արտանետման գործակից, գ/կմ | Արտանետում, կգ/ժամ | Բաժինը, % |
|---|---:|---:|---:|---:|
| Մարդատար ավտոմեքենա (car) | 1338 | 170 | 56,9 | 46 |
| Բեռնատար (truck) | 335 | 800 | 67,0 | 54 |
| **Ընդամենը** | **1673** | — | **123,9** | **100** |

Հաշվարկը ցույց է տալիս, որ բեռնատարները, որոնք կազմում են հոսքի ընդամենը 20%-ը, տալիս են CO₂-ի արտանետումների կեսից ավելին։ Սա հիմնավորում է մեքենաների դասակարգման կարևորությունը. միայն ընդհանուր քանակը հաշվող համակարգը չի կարող ճիշտ գնահատել արտանետումները։ Ստացված թվերը մոտավոր են, քանի որ իրական գործակիցները կախված են մեքենաների պարկի տարիքից, վառելիքի տեսակից, արագությունից և ճանապարհի թեքությունից։

Երթևեկության շարունակական մոնիթորինգը թույլ է տալիս՝

- բացահայտել խցանումների ժամերը և հատվածները, որտեղ արտանետումները առավելագույնն են,
- գնահատել բնապահպանական միջոցառումների (լուսացույցների կարգավորում, ծանր տրանսպորտի սահմանափակում, հասարակական տրանսպորտի զարգացում) արդյունավետությունը՝ համեմատելով «մինչև» և «հետո» վիճակները,
- օդի որակի չափիչ կայանների տվյալները համադրել երթևեկության իրական ծանրաբեռնվածության հետ,
- պլանավորել կանաչ գոտիները և աղմկապաշտպան պատնեշները ամենածանրաբեռնված հատվածներում։

**Ծրագրային միջոցի սեփական բնապահպանական ազդեցությունը։** Տեսախցիկներով մոնիթորինգը օգտագործում է արդեն տեղադրված սարքավորումները և, ի տարբերություն ինդուկտիվ օղակային տվիչների, չի պահանջում ճանապարհի ծածկույթի քանդում և վերականգնում, ինչը նվազեցնում է շինարարական թափոնները և ժամանակավոր խցանումները։ Աշխատանքում օգտագործվել են կոմպակտ YOLOv8n և YOLOv8s մոդելներ, որոնց ուսուցումը կատարվել է նոութբուքի վրա՝ առանց հզոր սերվերային գրաֆիկական պրոցեսորների։ Բոլոր ինը ուսուցման փորձերի ընդհանուր տևողությունը կազմել է մոտ 19,8 ժամ, և մոտ 60 Վտ միջին հզորության դեպքում ծախսված էլեկտրաէներգիան կազմում է մոտ 1,2 կՎտ·ժ, ինչը աննշան է մեծ մոդելների սերվերային ուսուցման համեմատ։ Տեսանյութը մշակվում է տեղում, և տվյալները չեն փոխանցվում արտաքին սերվերներ, ինչը նվազեցնում է նաև ցանցային և տվյալների կենտրոնների էներգածախսը։

Համակարգչային սարքավորումները պարունակում են ծանր մետաղներ և այլ վնասակար նյութեր, ուստի դրանց շահագործման ժամկետի ավարտից հետո դրանք պետք է հանձնվեն էլեկտրոնային թափոնների վերամշակման մասնագիտացված կազմակերպություններին և չպետք է տեղափոխվեն կենցաղային աղբավայրեր։

Այսպիսով, մշակված ծրագրային միջոցը կարող է ծառայել որպես երթևեկության բնապահպանական մոնիթորինգի տվյալների մատչելի աղբյուր՝ տրամադրելով արտանետումների գնահատման համար անհրաժեշտ ինտենսիվությունը ըստ դասերի, արագությունները և խտությունը, իսկ սեփական բնապահպանական ազդեցությունը նվազագույն է։


# ԳԼՈՒԽ 6. ԿԵՆՍԱԳՈՐԾՈՒՆԵՈՒԹՅԱՆ ԱՆՎՏԱՆԳՈՒԹՅՈՒՆ

## 6.1. ԵՐԹԵՎԵԿՈՒԹՅԱՆ ՏԵՍԱՀՍԿՈՒՄԸ ՈՐՊԵՍ ՃԱՆԱՊԱՐՀԱՅԻՆ ԱՆՎՏԱՆԳՈՒԹՅԱՆ ԱՊԱՀՈՎՄԱՆ ՄԻՋՈՑ

Ճանապարհատրանսպորտային պատահարները մարդկանց կյանքի և առողջության համար ամենալուրջ վտանգներից են։ Համաշխարհային առողջապահական կազմակերպության (ԱՀԿ) տվյալներով 2021 թվականին աշխարհում ճանապարհատրանսպորտային պատահարներում զոհվել է մոտ 1,19 միլիոն մարդ, և ճանապարհային վնասվածքները 5–29 տարեկան երեխաների և երիտասարդների մահվան հիմնական պատճառն են [22]։ Միլիոնավոր մարդիկ ստանում են ոչ մահացու վնասվածքներ, որոնք հաճախ հանգեցնում են հաշմանդամության։

Ճանապարհային անվտանգության հիմնական ռիսկի գործոններն են՝

- արագության գերազանցումը և պայմաններին չհամապատասխանող արագությունը,
- վարորդի ուշադրության շեղումը (հեռախոսի օգտագործում), հոգնածությունը և ոգելից խմիչքների ազդեցությունը,
- անվտանգության գոտիների և սաղավարտների չօգտագործումը,
- ճանապարհային ենթակառուցվածքի թերությունները (անբավարար լուսավորություն, գծանշում, հետիոտնային անցումներ),
- տրանսպորտային միջոցների անսարքությունը,
- երթևեկության խիտ և անկայուն հոսքը, որի դեպքում մեծանում է հետևից բախումների հավանականությունը։

Արագությունն ազդում է ինչպես պատահարի հավանականության, այնպես էլ դրա ծանրության վրա։ ԱՀԿ-ի գնահատմամբ միջին արագության 1 կմ/ժ աճը մոտ 3%-ով մեծացնում է վնասվածքներով պատահարի ռիսկը, իսկ մահացու պատահարի ռիսկը՝ 4–5%-ով [23]։ Բախման ժամանակ անջատվող էներգիան համեմատական է արագության քառակուսուն՝

> W = m · v² / 2  (6.1)

իսկ մեքենայի կանգառի ճանապարհը բաղկացած է վարորդի ռեակցիայի ընթացքում անցած ճանապարհից և արգելակման ճանապարհից՝

> S = v · tռ + v² / (2 · μ · g)  (6.2)

որտեղ v-ն արագությունն է, մ/վ, tռ-ն՝ վարորդի ռեակցիայի ժամանակը (մոտ 1 վ), μ-ն՝ անվադողի և ճանապարհի կառչման գործակիցը (չոր ասֆալտի համար մոտ 0,7), g-ն՝ ազատ անկման արագացումը (9,81 մ/վ²)։ Աղյուսակ 6.1-ում բերված են կանգառի ճանապարհի հաշվարկները տարբեր արագությունների համար, այդ թվում՝ տեսանյութ 1-ում ծրագրի չափած առավելագույն արագության համար։

Աղյուսակ 6.1 Կանգառի ճանապարհը տարբեր արագությունների դեպքում (tռ = 1 վ, μ = 0,7)

| Արագություն, կմ/ժ | Արագություն, մ/վ | Ռեակցիայի ճանապարհ, մ | Արգելակման ճանապարհ, մ | Կանգառի ճանապարհ, մ |
|---:|---:|---:|---:|---:|
| 60 | 16,7 | 16,7 | 20,2 | 36,9 |
| 90 | 25,0 | 25,0 | 45,5 | 70,5 |
| 120 | 33,3 | 33,3 | 80,9 | 114,2 |
| 154 (չափված առավելագույնը) | 42,8 | 42,8 | 133,4 | 176,2 |

Աղյուսակից երևում է, որ արագության աճը 90-ից 120 կմ/ժ (33%-ով) մեծացնում է կանգառի ճանապարհը 62%-ով, իսկ 154 կմ/ժ արագության դեպքում այն գրեթե 2,5 անգամ մեծ է, քան 90 կմ/ժ դեպքում։ Տեսանյութ 1-ում ծրագիրը չափել է 85-րդ պերցենտիլ արագությունը՝ 138,8 կմ/ժ, և առավելագույնը՝ 154,1 կմ/ժ, որոնք գերազանցում են մայրուղիների համար սովորաբար սահմանվող 110–130 կմ/ժ սահմանափակումները։ Նման տվյալները թույլ են տալիս ճանապարհային ծառայություններին բացահայտել վտանգավոր հատվածները։

**Երթևեկության վերլուծության ծրագրային միջոցի դերը անվտանգության ապահովման գործում։** Մշակված ծրագիրը կարող է օգտագործվել հետևյալ խնդիրների լուծման համար՝

- արագության ռեժիմի մոնիթորինգ. 85-րդ պերցենտիլ արագությունը ճանապարհային ճարտարագիտության մեջ օգտագործվում է արագության սահմանափակումներ նշանակելու և դրանց արդյունավետությունը գնահատելու համար,
- խտության և սպասարկման մակարդակի (LOS) վերահսկում և խցանումների վաղ հայտնաբերում, որոնց պոչում հաճախ տեղի են ունենում հետևից բախումներ,
- ծանր տրանսպորտի բաժնի որոշում ըստ ժամերի և ճանապարհային հատվածների,
- անվտանգության միջոցառումների (արագության սահմանափակում, լուսացույցի տեղադրում, գծանշման փոփոխություն) արդյունավետության գնահատում «մինչև» և «հետո» համեմատությամբ,
- լուսացույցային ցիկլերի պլանավորման համար ինտենսիվության տվյալների հավաքում։

**Անձնական տվյալների պաշտպանություն։** Տեսախցիկների տեսանյութերը կարող են պարունակել անձնական տվյալներ՝ մարդկանց դեմքեր և մեքենաների պետական համարանիշներ, որոնց մշակումը Հայաստանի Հանրապետությունում կարգավորվում է «Անձնական տվյալների պաշտպանության մասին» ՀՀ օրենքով [24]։ Մշակված ծրագիրը նախագծված է անձնական տվյալների ռիսկը նվազագույնի հասցնելու սկզբունքով՝

- տեսանյութը մշակվում է տեղում՝ օգտագործողի համակարգչում, և չի փոխանցվում արտաքին սերվերներ,
- ծրագիրը չի ճանաչում դեմքեր և համարանիշներ. յուրաքանչյուր մեքենա ստանում է միայն անանուն ժամանակավոր նույնացուցիչ (ID),
- արդյունքներում պահպանվում են միայն ամփոփ վիճակագրություն, հետագծերի կոորդինատներ և արագություններ։

Իրական շահագործման ժամանակ անհրաժեշտ է նաև սահմանափակել սկզբնական տեսանյութերի պահպանման ժամկետը և դրանց հասանելիությունը, ինչպես նաև տեղեկացնել հանրությանը տեսահսկման իրականացման մասին։

**Օպերատորի աշխատատեղի անվտանգությունը։** Ծրագրային միջոցի մշակման և շահագործման ժամանակ աշխատանքը կատարվում է համակարգչով, ուստի պետք է պահպանվեն համակարգչով աշխատանքի անվտանգության և էրգոնոմիկայի պահանջները՝

- մոնիտորը տեղադրվում է աչքերից 50–70 սմ հեռավորության վրա, էկրանի վերին եզրը՝ աչքերի մակարդակին կամ մի փոքր ցածր,
- աշխատատեղի լուսավորությունը պետք է լինի 300–500 լյուքս, առանց էկրանի վրա փայլատակումների և անդրադարձումների,
- յուրաքանչյուր 1–2 ժամ աշխատանքից հետո անհրաժեշտ է 10–15 րոպե ընդմիջում և աչքերի մարզում,
- աթոռը պետք է կարգավորելի լինի բարձրությամբ և մեջքի հենարանով, ոտքերը՝ հենված հատակին,
- սենքում պետք է պահպանվի բարենպաստ միկրոկլիմա (ջերմաստիճանը մոտ 20–24 °C, հարաբերական խոնավությունը 40–60%) և պարբերական օդափոխություն,
- էլեկտրական անվտանգության համար սարքավորումները պետք է միացվեն հողանցված վարդակներին, լարերը պետք է լինեն անվնաս, իսկ աշխատատեղում չպետք է լինեն հեղուկներ,
- հրդեհային անվտանգության համար սենքում պետք է լինի էլեկտրական սարքավորումների հանգցման համար նախատեսված (ածխաթթվային) կրակմարիչ։

Այսպիսով, մշակված ծրագրային միջոցը նպաստում է ճանապարհային անվտանգությանը՝ տրամադրելով արագության, խտության և երթևեկության կազմի օբյեկտիվ տվյալներ, միաժամանակ պահպանելով անձնական տվյալների պաշտպանության սկզբունքները։ Ծրագրի հետ աշխատելիս անհրաժեշտ է պահպանել համակարգչով աշխատանքի անվտանգության և էրգոնոմիկայի կանոնները։


# ԵԶՐԱԿԱՑՈՒԹՅՈՒՆՆԵՐ

Դիպլոմային աշխատանքում իրականացվել են.

- **Երթևեկության հոսքի բնութագրերի և տեսավերլուծության մեթոդների ուսումնասիրություն՝** վերլուծվել են ինտենսիվությունը, խտությունը, ժամանակային և տարածական միջին արագությունները, սպասարկման մակարդակը և դրանց չափման եղանակները։ Որպես դետեկտոր ընտրվել է YOLOv8 փաթույթային նեյրոնային ցանցը, հետագծման համար՝ ByteTrack ալգորիթմը, իսկ մետրական չափումների համար՝ ճանապարհային հարթության հոմոգրաֆիկ տրամաչափումը։
- **Ուսուցման տվյալների պատրաստում՝** երկու բաց աղբյուրներից պատրաստվել է հինգ դասի տրանսպորտային միջոցների վերարտադրելի կորպուս. VisDrone2019-DET (218 242 շրջանակ ուսուցման ընտրանքում) և MIO-TCD (30 000 պատկեր)։ Անկախ ստուգման համար առանձնացվել է UA-DETRAC հաջորդականություն։
- **CNN-ի ուսուցման փորձերի համեմատական վերլուծություն՝** կատարվել է տասը վերարտադրելի փորձ.
  - ուսուցման փոխանցումը սահմանափակ տվյալների պայմաններում բարձրացրել է mAP50-ը 2,6%-ից մինչև 13,8%,
  - մուտքի չափի մեծացումը 640-ից 960 պիքսել բարելավել է փոքր օբյեկտների հայտնաբերումը (34,7% → 45,9%),
  - ճանապարհային տեսախցիկների տվյալների ավելացումը վերացրել է տիրույթի տեղաշարժը (MIO-TCD-ում 15,1% → 83,7%),
  - ավելի մեծ YOLOv8s մոդելը և նրա ուսուցման երկարացումը ևս 12 դարաշրջանով բարելավել են արդյունքները երկու տիրույթներում. առաջարկվող vehicle-road-yolov8s-long մոդելն ունի 51,4% mAP50 VisDrone-ում և 90,2% MIO-TCD-ում։
- **Ծրագրային միջոցի մշակում՝** իրականացվել են հաշվման գծերի հատման կանոնը հիստերեզիսով, գծից արդեն անցած մեքենաների հաշվարկը և կրկնակի ID-ների զտիչը, արագության գնահատումը սահող պատուհանով, խտության, սպասարկման մակարդակի և q = k·v հավասարման հաշվարկը, ֆիզիկական հավաստիության ավտոմատ ստուգումը և սալիկային հայտնաբերումը։ Մշակվել են հայերեն միջերես, հրամանային տող, ուղիղ հոսքի աջակցություն և արդյունքների արտահանում։ Ծրագիրը ծածկված է 76 ավտոմատ թեստով։
- **Ծրագրային միջոցի փորձարկում՝**
  - անկախ UA-DETRAC տեսանյութում առաջարկվող մոդելը հայտնաբերել է մեքենաների 99,0%-ը և ճիշտ հաշվել բոլոր 5 հատումները,
  - մայրուղու տեսանյութում ճիշտ են հաշվվել բոլոր 10 մեքենաները՝ ճիշտ ուղղություններով և ճիշտ խմբերով՝ 8 թեթև և 2 ծանր (երկու բեռնատարները դասակարգվել են որպես ավտոբուս, թեև թեստային ընտրանքում այդ շփոթումը մոտ 2% է),
  - արագության երկու անկախ եղանակները համընկնում են միջինը 2–3%-ի սահմաններում,
  - հավաստիության ստուգումն ավտոմատ կերպով հայտնաբերել է արագացված տեսանյութը։
- **Տեխնիկատնտեսական հաշվարկ, կենսագործունեության անվտանգության և բնապահպանության վերաբերյալ քննարկումներ՝** ծրագրային միջոցի ինքնարժեքը կազմում է 11 669 262 դրամ, իսկ բացթողման գինը՝ 16 523 675 դրամ։ Ցույց է տրվել, որ ծրագիրը կարող է օգտագործվել արտանետումների գնահատման և ճանապարհային անվտանգության մոնիթորինգի համար՝ պահպանելով անձնական տվյալների պաշտպանության սկզբունքները։

Ստացված արդյունքներն ունեն որոշակի սահմանափակումներ. արտաքին ստուգման ծավալը փոքր է, արագության բացարձակ ճշտությունը չի ստուգվել անկախ չափիչով, իսկ բոլոր տեսանյութերը ցերեկային են։ Աշխատանքի զարգացման հիմնական ուղղություններն են հաշվարկի ստուգումը տասնյակ նշագրված տեսանյութերով (գիշերը, անձրևի ժամանակ և խցանումներում), լրացուցիչ ուսուցումը Հայաստանի ճանապարհների տեսախցիկների պատկերներով, հաշվարկը ըստ առանձին երթևեկության գոտիների և ավտոմատ տրամաչափումը ճանապարհի գծանշումից։

Մշակված ծրագրային միջոցը կարող է օգտագործվել երթևեկության ուսումնասիրությունների, ուսումնական նպատակների և ավելի մեծ ինտելեկտուալ տրանսպորտային համակարգերի նախատիպի համար։

### Հավելված Բ. Հաշվման կանոնի ելակետային կոդը

Ստորև բերված է `traffic_cnn/counting.py` մոդուլի հիմնական մեթոդը, որը որոշում է հետագծի կողմը հաշվման գծի նկատմամբ և գրանցում է հատումը (3.1 բաժին)։

```
def update(self, identity, point, frame, size=None):
    ax, ay = self.a
    dx, dy = self.b[0]-ax, self.b[1]-ay
    distance = (dx*(point[1]-ay)-dy*(point[0]-ax))/self.length
    side = 1 if distance > self.margin else -1 if distance < -self.margin else 0
    if (identity not in self.previous and identity not in self.started
            and identity not in self.counted and size
            and abs(distance) <= self.start_fraction*size and self._on_segment(point)):
        self.started[identity] = (frame, distance, point, size)
    if not side:
        return None
    if identity in self.started:
        direction = self._started_crossing(identity, distance, side, frame)
        if direction:
            self.previous[identity] = (point, distance, side, frame)
            return direction
    old = self.previous.get(identity)
    self.previous[identity] = (point, distance, side, frame)
    if (old is None or identity in self.counted or side == old[2]
            or frame-old[3] > self.max_gap):
        return None
    t = old[1]/(old[1]-distance)
    cross = tuple(old[0][i]+t*(point[i]-old[0][i]) for i in range(2))
    if not self._on_segment(cross):
        return None
    self.started.pop(identity, None)
    return self._count(identity,
        'negative_to_positive' if side == 1 else 'positive_to_negative')
```

Արագության գնահատիչի հիմնական մեթոդը (`traffic_cnn/calibration.py`, 3.1 բաժին).

```
def update(self, identity, point, frame, t=None):
    if not self.calibration.contains(point):
        return self.current(identity)
    t = frame / self.fps if t is None else t
    world = self.calibration.to_world(point)[0]
    track = self.points.setdefault(identity, deque())
    if track and t - track[-1][0] > self.window:
        track.clear()
    track.append((t, world))
    while track and t - track[0][0] > self.window:
        track.popleft()
    span = t - track[0][0]
    if span >= self.min_span:
        kmh = float(np.linalg.norm(world - track[0][1]) / span * 3.6)
        self.raw.append(kmh)
        if kmh <= self.max_kmh:
            self.accepted += 1
            self.estimates.setdefault(identity, deque(maxlen=self.history)).append(kmh)
            self.all_estimates.setdefault(identity, []).append(kmh)
        else:
            self.rejected += 1
    return self.current(identity)
```
